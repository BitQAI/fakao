## Task 5：看背自定义范围排序优化（后端 service.py）

**文件**：
- `backend/app/service.py`（`custom_entries` 函数）

**内容**：
- [ ] `custom_entries(listen_only=False)`：排序 key 调整为 `(read_count, priority_order, subject_order, id)`，即 `read_count=0` 优先，其次 `read_count` 升序。
- [ ] 需在 SQL 或 Python 层面获取 `read_count`（复用 `review_stats.attach_read_counts` 逻辑），注意性能：先查所有候选条目，再批量附加计数，最后排序切片。
- [ ] 单元测试：验证排序顺序。

## Task 6：听学自定义范围排序优化（后端 service.py）

**文件**：
- `backend/app/service.py`（`_listen_pool` 函数）

**内容**：
- [ ] `_listen_pool`：分组逻辑不变（`never` = 未听，`heard` = 已听），但排序 key 调整：
  - `never`：`(listen_count=0, priority_order, subject_order, id)` → 本身全为 0，保持原序。
  - `heard`：`(listen_count 升序, last_ts 升序(越久越前), priority_order, subject_order, id)`。
- [ ] `heard` 组内先按 `listen_count` 升序，同计数下按 `last_ts` 升序（更久未听优先）。
- [ ] `custom_entries(listen_only=True)` 复用 `_listen_pool` 排序，自动生效。
- [ ] 单元测试：验证听学池与自定义听学排序。

## Task 7：后端 `/api/quiz/today` 支持 regenerate 参数

**文件**：
- `backend/app/routers/quizzes.py`
- `backend/app/quiz_service.py`

**内容**：
