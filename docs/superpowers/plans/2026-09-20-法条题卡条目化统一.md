## Task 2 — 卡片条目生成脚本

**文件**

- `backend/app/card_entries.py`（新，≤300 行）：ID 生成 / 字段映射 / `text_hash` / upsert。
- `backend/scripts/sync_card_entries.py`（新）：CLI（`--dry-run`、`--limit`、`--subject`）。
- `backend/tests/test_card_entries.py`（新）。

**接口**

- `card_entries.entry_id_for(subject, quiz_id) -> str`：`<科目前缀>-Q<quiz_id:06d>`。
- `card_entries.quiz_id_of(entry_id) -> int | None`：解析 `-Q` 后数字。
- `card_entries.upsert(conn, quiz_row, *, dry_run=False) -> str`：`created | updated | archived | same`。
- 科目前缀映射：商经知劳环 `SJ`、三国法 `SG`、理论法 `LL`、刑诉 `XS`、民诉 `MS`、民法 `MF`、
  行政法 `XZ`、刑法 `XF`（复用 `generate_entries.SUBJECT_PREFIX`，不重复定义）。

**步骤**

- [ ] 2.1 实现映射（Spec §2.2 表格逐字段落代码）
- [ ] 2.2 条文摘要用 `statute_cards.snippet`，朗读文本用 `statute_cards.listen_text`
- [ ] 2.3 upsert：存在→按 hash 判定是否更新；题库 `archived`→卡片 `status='draft'`
- [ ] 2.4 文本变化时删除 `data/audio/<卡片ID>.wav` 与 `tts_assets` 台账
- [ ] 2.5 `--dry-run` 输出将新建/更新/下架的条数
- [ ] 2.6 单测：ID 规则、1:1 反查、幂等（跑两遍第二遍全 `same`）、下架处理
- [ ] 2.7 真实运行：生成 13160 张卡片

**验证**：卡片数 == 已发布法条驱动题数；题目↔卡片 1:1；重跑第二遍 0 变更；
`/api/plans/today` 与 `/api/listen` 已能看到卡片条目（顺序按 `_sort_key` 的优先级）。
