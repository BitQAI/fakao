# 每日案例（微主观题）— 实施计划（2026-09-20）

> 依据：`docs/superpowers/specs/2026-09-20-法条库补全检索与知识库扩容-design.md` 第 5 节（Phase 2）

## 前置

- DeepSeek API 已探活通过（2026-09-20），采分点可真实生成。
- 案例库 7172 条，其中「人民法院案例库」5537 条、含明确「争议焦点」段 1752 条，是候选池。
- 不依赖法条正文入库，采分点的法条依据用现有 55 部法条校验。

## 任务清单

### Task 1 — 数据模型

文件清单：`backend/app/db.py`

- [x] `case_questions`：题干、设问、采分点、参考答案、状态、`(source, loc)` 唯一
- [x] `case_attempts`：作答记录（mode=write|listen、命中采分点、得分、耗时）
- [x] 索引 `idx_case_attempts_q`、`idx_case_questions_status`

### Task 2 — 服务层 `app/case_quiz.py`

- [x] `pick_daily(conn, day)`：优先没做过的 `published`，同日结果稳定（用日期序号轮换）
- [x] `public_payload(q)`：下发题干与设问，**不含答案与采分点**（有测试守护）
- [x] `submit_answer(...)`：落 attempt，返回采分点核对表
- [x] `grade(...)`：算分（命中数/总数）、返回未命中点及其法条依据
- [x] `statute_link(...)`：转成 `/statutes?law=&no=`；**该法不在法条库时不给链接**（否则前端撞 404）
- [x] `listen_text(q)`：只听模式朗读文本，只读题干与设问
- [x] `history` / `stats_summary`
- [x] 文件 ≤ 300 行

**范围决策（与 Spec 的偏差，需用户确认）**：Spec 写的是「未命中的采分点自动写入错题/复习池」。
本轮**不自动写 `reviews`**——现有 `reviews` 的 `bad` 会直接进调度队列，而案例题的"没写到"
不等于"知识点没记住"，硬写会把合成数据混进真实复习历史。改为：未命中采分点随作答记录留存，
并在前端给出「查看依据法条 / 查看相关考点」直达链接。

### Task 3 — 生成脚本 `scripts/build_case_questions.py`

- [x] 候选筛选：`source='人民法院案例库'` + 正文含「争议焦点」+ 关键词归类到考纲科目
- [x] LLM 加工：压缩案情（120–400 字）+ 2–3 设问 + 3–5 采分点（每点带法条依据）+ 参考答案
- [x] 校验：题干长度、设问数、采分点数、每条采分点至少一个法条可解析
- [x] 落库 `status='draft'`，`(source, loc)` 幂等；`--publish` 才置 `published`
- [x] 参数：`--limit`、`--subject`、`--dry-run`、`--publish`、`--relax`（法条库未补全时放行）
- **实测结果**：生成 13 道（刑法 4 / 民法 3 / 行政法 3 / 民诉 2 / 刑诉 1），已全部 `published`；
  2 道因题干超长被校验挡掉

### Task 4 — API `app/routers/cases_quiz.py`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/cases/daily` | 今日案例题（不含答案与采分点） |
| POST | `/api/cases/{id}/answer` | 提交要点，返回采分点核对表 |
| POST | `/api/cases/{id}/grade` | 提交勾选，返回得分与未命中点 |
| GET | `/api/cases/history` | 历史与统计 |
| GET | `/api/cases/{id}` | 单题详情（含参考答案，复习用） |
