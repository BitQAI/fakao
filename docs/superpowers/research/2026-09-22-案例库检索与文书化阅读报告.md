## 2. 实测数据

### 2.1 案例库规模（`GET /api/case/stats`）

```
total 7172 = 人民法院案例库 5537 + 司法部案例库 1100 + 最高检指导性案例 257 + 最高法指导性案例 278
```

### 2.2 检索（单进程、冷缓存，7172 行 LIKE 扫描）

| 关键词 | 命中 | 耗时 |
|---|---|---|
| 房屋租赁 | 30（上限截断） | 264 ms |
| 抢劫 既遂 | 14 | 109 ms |
| 正当防卫 明显超过必要限度 | 22 | 91 ms |
| 表见代理 | 19 | 91 ms |
| 生态环境 | 30（上限截断） | 100 ms |

多词为 AND 语义；标题命中权重最高（6），其次案号（4）、关键词（3）、类别（2）、正文（1）。

### 2.3 文书分节（真实案例抽检）

| 案例 | 小节 |
|---|---|
| 人民法院案例库 `case_00001` | 裁判要旨 / 相关法条 / 正文 / 审理程序 |
| 人民法院案例库 `case_01020` | 相关法条 / 正文 / 审理程序（自动合并重复 3 句） |
| 最高检 `检例第39号` | 关键词 / 要旨 / 相关规定 / 基本案情 / 指控与证明犯罪 / 指导意义 |
| 最高法 `指导性案例001号` | 关键词 / 裁判要点 / 相关法条 / 基本案情 / 裁判结果 / 裁判理由（自动去掉重复标题行 + 1 处重复） |
| 司法部 `case_00001` | 案情简介 / 调解过程 / 调解结果 / 案例点评 |

清洗口径：markdown 标题与分隔线、批次元信息行、残留的下一篇案例标题（最高检）、
人民法院案例库正文末尾的关联法条行与一审/二审行（800 条样本中 660 条含程序行、569 条含法条行）、
连续重复的句子块（全库 30 个案例存在该脏数据）。

## 4. 遗留与后续

- `backend/app/case_index.py` 329 行，略高于项目软上限 300（硬上限 500，未越线）。若要拆分，
  建议按职责切成 `case_sections.py`（文书分节）+ `case_index.py`（检索/统计），需用户确认后执行。
- 检索为 `LIKE` 全表扫描，7172 行下 100–260 ms；案例量级翻十倍再考虑 SQLite FTS5。
- 案例页暂未做「相关法条 / 相关条目」反查与收藏、朗读，属后续独立需求。
- 条目挂接案例的 `SourceViewer` 弹层仍按纯文本展示（本期有意不动，避免影响看背/听学主路径）。
