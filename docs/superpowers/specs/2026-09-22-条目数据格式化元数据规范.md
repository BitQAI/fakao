# 条目数据格式化元数据规范（fakao-entry）

> 版本：1.0 | 日期：2026-09-22 | 状态：生效
> 适用：任何要变成「条目」的上游文件——资料汇编、真回忆版、讲义、外部题库、历年真题。
> 配套：`backend/app/importer.py`（硬校验的唯一实现）、`backend/scripts/validate_entries.py`（入库前干跑）、
> `docs/superpowers/specs/2026-08-25-客观题条目数据框架-design.md`（字段语义的原始设计）。

---

## 0. 一句话口径

**上游文件 → 批次清单 → `fakao-entry/1.x` 条目 JSON → 干跑校验（errors=0）→ 入库 → 提升 `final` → 音频 → 案例挂接。**
任何一步跳过都算没导入：JSON 写完只是「半成品」，库里查得到再看得到才算成品。

---

## 1. 分层模型（各层只干一件事）

| 层 | 载体 | 职责 | 权威性 |
|---|---|---|---|
| L1 源料 | `data/科目资料/`、`data/真题回忆*/`、外部投递文件 | 原始文本，只读不改 | 事实来源 |
| L2 批次清单 | `data/batches/<批次名>/manifest.json` | 记录本批次的来源、可信度、题量核对、ID 段位 | 审计依据 |
| L3 条目文件 | `data/entries/<科目>.json` | `fakao-entry/1.x` 侧车 JSON，git 跟踪 | git 是权威 |
| L4 库 | `data/fakao.db` | `entries` / `quizzes` / `cases` | 可重建 |
| L5 消费 | 看背 / 听学 / 自测 / 法条页 / 案例库 | 只读 | 派生 |

**重建优先**：L4 永远可以由 L1–L3 重建（`README.md` 部署 B 方案），所以 L3 的规范性比 L4 重要。

## 2. L2 批次清单 `manifest.json`

### 2.1 位置与命名

```
data/batches/2026-真题客观题-回忆版/
├── manifest.json          # 必填，本批次元数据
├── raw/                   # 可选，本批次原始投递件（.md/.csv/.json）
└── entries/               # 可选，本批次产出的中间条目 JSON（导入前在此校验）
```

批次名 = `YYYY-<来源或性质>-<版本>`，同一批次的再次修正用 `-v2` 后缀，**不覆盖旧批次**。

### 2.2 字段表

| # | 字段 | 类型 | 必填 | 约束 / 说明 | 示例 |
|---|---|---|---|---|---|
| 1 | `batch_id` | string | 是 | 与目录名一致，全局唯一 | `2026-真题客观题-回忆版` |
| 2 | `source_kind` | enum | 是 | `资料` / `真题` / `讲义` / `外部题库` / `法条` | `真题` |
| 3 | `year` | int | 是 | 命题年度 | `2026` |
| 4 | `creator` | string | 是 | 整理者（人 / 机构 / `llm:deepseek-chat`） | `考生回忆+机构整理` |
| 5 | `created_at` | string | 是 | ISO 日期 | `2026-09-22` |
| 6 | `trust` | enum | 是 | 批次整体可信度 `A`/`B`/`C`/`D`（见 §5.3） | `C` |
| 7 | `raw_files` | string[] | 是 | 相对仓库根的源料路径 | `["data/真题回忆/2026-客观题-回忆整理.md"]` |
| 8 | `expected_units` | int | 是 | 上游声称的原始单元数（真题=题数） | `400` |
| 9 | `counted_units` | int | 是 | 实际清点到的单元数，**必须与 `expected_units` 对账** | `400` |
| 10 | `unit_breakdown` | object | 是 | 单元数分组（真题按卷次），键值均为 int | `{"0912-卷一":100,...}` |
| 11 | `subject_map` | object | 否 | 上游科目名 → 本库科目名的映射 | `{"商经法":"商经知劳环"}` |
| 12 | `id_range` | object | 是 | 本批次占用的 ID 段位：科目 → `[起始, 结束]` | `{"XF":[700,760]}` |
| 13 | `entry_files` | string[] | 是 | 产出的条目 JSON 路径 | `["data/entries/刑法.json"]` |
| 14 | `products` | enum[] | 是 | 本批次产出的产物：`entry`/`quiz`/`card` | `["entry","quiz"]` |
| 15 | `status` | enum | 是 | `planned` → `validated` → `imported` → `done` | `validated` |
| 16 | `notes` | string | 否 | 冲突、存疑、弃用条目数的说明 | `答案冲突 12 题已弃用` |

### 2.3 示例

```json
{
  "batch_id": "2026-真题客观题-回忆版",
  "source_kind": "真题",
  "year": 2026,
  "creator": "考生回忆+机构整理",
  "created_at": "2026-09-22",
  "trust": "C",
  "raw_files": [
    "data/真题回忆/2026-客观题-回忆整理.md",
    "data/真题回忆版/法考回忆版真题-近3年.md"
  ],
  "expected_units": 400,
  "counted_units": 400,
  "unit_breakdown": {
    "0912-卷一": 100, "0912-卷二": 100,
    "0913-卷一": 100, "0913-卷二": 100
  },
  "subject_map": {"商经法": "商经知劳环", "国际公法": "三国法"},
  "id_range": {"XF": [700, 719], "MF": [700, 716], "SJ": [700, 712]},
  "entry_files": ["data/entries/刑法.json", "data/entries/民法.json"],
  "products": ["entry", "quiz"],
  "status": "validated",
  "notes": "回忆版答案冲突 12 题只入题库不入条目"
}
```

## 3. L3 条目级元数据规范

### 3.1 文件外壳

```json
{
  "schema": "fakao-entry/1.0",
  "source_md": "<生成该文件的源料目录，仅记录用>",
  "status": "draft",
  "generated_at": "2026-09-22T10:00:00",
  "count": 162,
  "entries": [ ... ]
}
```

- `schema` 必须精确等于 `fakao-entry/1.0`，否则 `importer.load_payload` 直接抛错（整文件拒收）。
- `status` 必须是 `draft`；**`final` 只能由导入后的 SQL 提升**，不允许写在文件里。
- `count` 必须等于 `entries` 长度（自查项，importer 不校验）。

### 3.2 条目字段表（14 字段）

硬校验口径见 §6；`E*` = 硬错误（整批拒绝），`W*` = 软警告（照常入库）。

| # | 字段 | 类型 | 必填 | 约束 | 示例 |
|---|---|---|---|---|---|
| 1 | `id` | string | 是 | 正则 `^(MF\|XF\|XS\|MS\|SJ\|LL\|SG\|XZ)-\d{3}$`，全局唯一（`E3`） | `XF-701` |
| 2 | `subject` | enum | 是 | 8 科之一，且与 ID 前缀一致（见 §4） | `刑法` |
| 3 | `submodule` | string | 是 | `编-节` 式二级模块，建议复用同科目已有取值 | `分则-财产犯罪` |
| 4 | `point` | string | 是 | 大纲语言考点名，建议 ≤15 字 | `转化型抢劫` |
| 5 | `anchor` | string | 是 | 场景/案情锚点句，建议 16–42 字，不以句号结尾（`E5` 仅查非空） | `甲盗窃后被失主当场扭住，为挣脱反抗将失主打成轻伤` |
| 6 | `conclusion` | string | 是 | 一句话独立成立，句末带句号，涉及法条须写完整条号 | `成立抢劫罪：犯盗窃、诈骗、抢夺罪后为抗拒抓捕当场使用暴力（刑法第269条）。` |
| 7 | `priority` | enum | 是 | `高频考点`/`易错陷阱`/`新增必考`/`普通`（`E4`） | `高频考点` |
| 8 | `rationale` | string | 是 | 为什么值得记（一句话） | `转化型抢劫历年必考，2026 真题复用` |
| 9 | `sources` | object[] | 是 | ≥1 条；每条至少含 `type`/`ref`/`loc`（`E6`） | `[{"type":"真题","ref":"2026-客观题-回忆整理.md","loc":"3.3.1"}]` |
| 10 | `statutes` | string[] | 是 | 可空数组（纯理论考点给 `[]`）；元素为 `法名+条号`，解析失败只告警（`W3`） | `["刑法269条"]` |
| 11 | `tts_text` | string | 是 | **必须非空**（空串按 `E2` 拒收）；格式 `【科目·考点】+ 场景 + 结论`，建议 ≤150 字，禁 Markdown 标记 | `【刑法·转化型抢劫】甲盗窃后被失主当场扭住…成立抢劫罪。` |
| 12 | `note` | string | 否 | 易错陷阱/关联考点，仅阅读视图展示 | `“当场”含追捕途中；14–16 岁不成立转化型抢劫。` |
| 13 | `cases` | object[] | 否 | ≤3 条，每条恰好 `{source, loc}`，`source` 取 4 库枚举，`(source,loc)` 必须在统一索引存在（`E7`）；`title` 由 importer 自动补全 | `[{"source":"人民法院案例库","loc":"case_00001"}]` |
| 14 | `kind` | string | 否 | 条目文件里省略或写 `entry`；`card` 由 `sync_card_entries.py` 重建，**禁止手写** | — |

### 3.3 `sources.type` 受控词表

`高频` / `易错` / `新增` / `真题` / `讲义` / `外部` / `法条`。新类型要先进本表再加使用，避免检索口径分裂。

### 3.4 写作口径（影响可用性，无硬校验）

- `anchor` 面向耳朵：一个具体场景，能独立听懂，不复述法条原文。
- `conclusion` 面向机器：句号结尾、法条完整条号，可被 `statutes` 字段的校验对齐。
- `anchor`+`conclusion` 拼起来必须能自洽成一问一答（听学时只读这两句 + `tts_text`）。
- `point` 在同科目内不得重复；同考点、不同场景应合并为一条并把场景差异写进 `note`。

## 4. ID 分配规范

### 4.1 前缀表（与 `scripts/generate_entries.py:SUBJECT_PREFIX` 一致）

| 科目 | 前缀 | 科目 | 前缀 |
|---|---|---|---|
| 刑法 | `XF` | 民诉 | `MS` |
| 民法 | `MF` | 商经知劳环 | `SJ` |
| 刑诉 | `XS` | 理论法 | `LL` |
| 三国法 | `SG` | 行政法 | `XZ` |

> 口径提醒：**商经知劳环** = 商法 + 经济法 + 知产 + 劳动社保 + 环境资源；ID 前缀仍为 `SJ`。

### 4.2 分配规则

1. 每个科目一个连续序号空间，导入前先取当前最大值：
   `SELECT MAX(CAST(substr(id,4) AS INTEGER)) FROM entries WHERE id LIKE 'XF-%' AND id NOT LIKE 'XF-Q%'`
2. 新批次从 `max+1` 开始连续分配，**不留空洞、不复用已删除 ID**（git 历史里删过的 ID 也视为占用）。
3. 批次清单 `id_range` 必须登记本批次占用区间；多批次并行时必须先看有没有已登记的未导入区间。
4. 序号是 3 位（`001`–`999`）。单科目逼近 999 时：**先停**，把 `importer.ID_PATTERN` 与本文档同步升级到 4 位并一次性迁移，禁止在一个科目里混用 3 位与 4 位。

## 5. 真题批量导入规范（以「2026 年真题」为例）

### 5.1 输入的默认形态

上游典型形态（实测 `data/真题回忆/2026-客观题-回忆整理.md`、`data/真题回忆版/法考回忆版真题-近3年.md`）：

```markdown
### 12.（刑法·共同犯罪·抢劫）<题干……>？
A. …
B. …
**答案：B**
**解析**（考点：抢劫罪结果加重犯、共犯脱离）：A项错误——…
```

### 5.2 单元清点与切分（导入前必须先对账）

2026 年客观题为 **2 个批次 × 2 卷 × 100 题 = 400 题**，两批次不是同一套卷：

| 单元 | 划分依据 | 题量 |
|---|---|---|
| `0912-卷一` | 9 月 12 日上午（公法卷） | 100 |
| `0912-卷二` | 9 月 12 日下午（私法卷） | 100 |
| `0913-卷一` | 9 月 13 日上午（公法卷） | 100 |
| `0913-卷二` | 9 月 13 日下午（私法卷） | 100 |

切分规则：

1. 回忆版**不保证 400 题全部还原**。因此 `counted_units` 记录「清点到的题」，缺题必须在 `notes` 写明缺口数量与已知题号。
2. 题号原样保留在 `sources.loc`（如 `0912-卷二-T053`）；题号缺失时用文档内序号，并在 `note` 标注「题号未还原」。
3. 同一题在不同来源重复出现时，按「题干前 30 字 + 答案」做去重键，保留信息最全的一份，其余记入 `sources` 追加引用。

### 5.3 可信度分级 → 入库口径（硬性）

| 级别 | 内容 | 允许的产物 |
|---|---|---|
| A | 考试安排、分值结构等事实 | 只进 `notes`，不产条目 |
| B | 考点清单（多来源交叉印证） | 产条目（`sources.type=真题`），可标 `高频考点` |
| C | 单题题干 + 选项还原 | 产题库；**仅当**该考点另有资料支撑时才产条目 |
| D | 参考答案 + 解析（机构自答） | 只作为 `note`/`analysis` 的参考，**不得**作为 `conclusion` 的唯一依据 |

答冲突题（同一题两套答案）：不产条目，只入题库并在 `analysis` 标记「答案存疑」。

### 5.4 字段映射（一道客观题 → 条目）

| 条目字段 | 取自真题的哪一部分 | 处理要求 |
|---|---|---|
| `id` | 按 §4 分配 | 批次清单登记段位 |
| `subject` / `submodule` | 标题里的 `（刑法·共同犯罪·抢劫）` | 用 `subject_map` 归一（`商经法`→`商经知劳环` 等） |
| `point` | 括号内最末一个考点词（`抢劫`）或解析的「考点：」 | 与已有 `point` 去重，重复则并入旧条目的 `note` |
| `anchor` | 题干情景 | 压缩为 16–42 字场景句，删选项编号与无关人名 |
| `conclusion` | 答案字母 + 解析首句结论 | 写成人话 + 完整条号；只信 B 级考点与法条原文 |
| `priority` | B 级高频 → `高频考点`；新法修订 → `新增必考`；陷阱型 → `易错陷阱`；其余 `普通` | 由考点频次（真题+资料命中次数）决定，别按手感 |
| `rationale` | 「2026 真题 <卷次>-T<题号>」 | 必写，便于日后回溯 |
| `sources` | `{"type":"真题","ref":"2026-客观题-回忆整理.md","loc":"0912-卷二-T053"}` | `ref` 必须是仓库内真实文件名，否则 `W1` |
| `statutes` | 解析里引用的法条 | 解析无法条时留 `[]`（不编造） |
| `note` | 干扰项错在哪、回忆版存疑点 | ≤80 字 |
| `tts_text` | 由考点与结论改写、或复用条目 | 必须非空（空串是 `E2`）；直接借用已有条目的朗读稿更省事，避免手写 |

### 5.5 产物拆分（一批真题产出三类东西，别混）

| 产物 | 表 | 口径 |
|---|---|---|
| 题库题 `quiz` | `quizzes` | 400 题原样入库（含选项、答案、解析），供自测/组卷。**`origin` 需在 DB 里扩到 `exam`**，属表结构改动，须与迁移同提交 |
| 考点条目 `entry` | `entries`（`kind='entry'`） | 由 B 级考点 + 考点去重派生，量级经验值：400 题 → 120–200 条 |
| 法条题卡 `card` | `entries`（`kind='card'`） | 真题**不直接**产卡片；卡片只由题库/法条重建（`sync_card_entries.py`） |

### 5.6 真题批次的验收标准

1. `counted_units` 与清点结果一致，缺口在 `notes` 有说明；
2. 条目数 ≥ 去重后考点数，且 `point` 在同科目内 0 重复；
3. 干跑 `errors=0`；`W1`/`W2`/`W3` 逐条确认或修正；
4. 导入后 `final` 提升成功，`SELECT COUNT(*) FROM v_entries WHERE status='final'` 增量等于本批次新增条目数；
5. 覆盖检查：`generate_entries.py --subject <科目> --gaps --dry-run` 显示本批次主要考点已不再报缺口。

## 6. 校验规则清单（与 `importer.py` 一一对应）

### 硬错误（有一条即整文件拒收）

| 码 | 规则 | 实现位置 |
|---|---|---|
| `E1` | `schema != fakao-entry/1.0` | `load_payload` |
| `E2` | 缺少 §3.2 的任一必填字段 / 值为空字符串 | `validate_entry` |
| `E3` | `id` 不匹配前缀-3 位数字 | `ID_PATTERN` |
| `E4` | `priority` 不在枚举内 | `PRIORITIES` |
| `E5` | `anchor` 或 `conclusion` 为空 | `validate_entry` |
| `E6` | `sources` 为空数组，或元素缺 `type`/`ref`/`loc` | `validate_entry` |
| `E7` | `cases` 超过 3 条、元素不是恰好 `{source,loc}`、`source` 不在 4 库枚举、或 `(source,loc)` 不在统一索引 | `_validate_cases` |

### 软警告（照常入库，必须逐条确认）

| 码 | 规则 | 处理建议 |
|---|---|---|
| `W1` | `sources[].ref` 在 `data/` 树下找不到同名文件 | 改文件名或补投递源料 |
| `W2` | `sources[].loc` 摘录文本在该文件里搜不到 | 抄错/改写过度，按原文校对 |
| `W3` | `statutes[]` 无法解析到法条库 | 补 `STATUTE_ALIASES` 或修引用写法 |
| `W4` | `anchor` 过短（<16 字）、`conclusion` 超长（>60 字）等建议区间越界 | 语义完整可放行，否则重写 |

> `W4` 由 `scripts/generate_entries.py` 在生成阶段打；`validate_entries.py` 会把同一口径一起报出来。

## 7. 导入流水线（每批次照抄执行）

```bash
cd backend

# 1. 干跑校验：不写库，只报 E/W（errors=0 才继续）
.venv/bin/python scripts/validate_entries.py ../data/batches/2026-真题客观题-回忆版/entries/*.json

# 2. 入库（注意：只改这几科的文件，别整目录通配）
.venv/bin/python scripts/import_entries.py ../data/entries/刑法.json ../data/entries/民法.json

# 3. 提升 final（漏了这步，全库查询都看不到新条目）
.venv/bin/python -c "from app import db; c=db.connect(); print(c.execute(\"UPDATE entries SET status='final' WHERE status='draft'\").rowcount); c.commit(); c.close()"

# 4. 音频（幂等，只补缺失）
.venv/bin/python scripts/synthesize_audio.py

# 5. 案例挂接（只处理 cases 为空的条目）
.venv/bin/python scripts/match_cases.py

# 6. 覆盖检查
.venv/bin/python scripts/generate_entries.py --subject 刑法 --gaps --dry-run

# 7. 回归测试
.venv/bin/python -m pytest tests
```

批次清单 `status` 随流程推进：`planned` → `validated` → `imported` → `done`。

## 9. 常见错误速查

| 现象 | 原因 | 处置 |
|---|---|---|
| 导入成功但全库看不到新条目 | 忘了提升 `final` | 执行 §7 第 3 步 |
| 整文件被拒，报一堆 `缺少必填字段` | 上游字段名用了中文或自造名 | 按 §3.2 字段表重命名，缺的补空 |
| `schema 不符` | 文件头写了 `fakao-entry/1.1` 之类 | 统一回 `fakao-entry/1.0`（升级 schema 需先改 importer） |
| 案例挂接时被裁剪 | 追加案例后超 3 条上限 | 优先保留指导性案例，其余移入 `note` |
| 同一考点重复多条 | 没有按 `point` 去重 | 合并为一条，场景差异进 `note` |
