# 关系型判断题（判断题扩容：情态词 / 程序层级 / 易混概念对）— Spec（2026-09-20）

## 1. 问题背景

现有「判断题」入口（`origin='judge'`, `qtype='judge'`）在代码层是**数字判断题专属**：
硬闸门 `backend/app/number_terms.py` 规定「题干里没有数字表达即丢弃」，错题只允许改写一处数字。
实测题库 1408 道全部是数字型（`对` 769 / `错` 639），覆盖 944 条法条。

因此用户点名的这几类考点目前**一道都出不来**：

- 情态/权限词：可以 / 应当 / 必须 / 不得 / 无须 / 有权 / 无权 / 报请批准 / 备案
- 形式与文书：决定 / 决议 / 裁定 / 判决
- 程序层级：一审 / 二审 / 再审 / 重审 / 发回重审 / 独任 / 合议庭 / 复议 / 复核
- 易混程序行为：反诉 / 抗诉 / 撤回起诉 / 驳回起诉 / 驳回诉讼请求 / 不予受理

这些恰恰是法考客观题最高频的「偷换一处措辞」式陷阱，与数字题同属「可核验判断题」，
应当并入同一个判断题池，用同一套「依据原文可核验」的思路约束，而不是靠 LLM 自由发挥。

## 2. 目标与非目标

### 2.1 目标

- G1：判断题从「数字型」扩展为「数字型 + 关系型」，两类混排进现有判断题入口。
- G2：新增关系词闸门（`app/relation_terms.py`），保证题干里的关系词可回溯到依据原文；
  「错」题只允许按白名单**定向偷换一个关系词**。
- G3：覆盖口径**全量**，不做小批量试产：法条侧按「条文 × 词族」出题，条目侧逐条出题。
- G4：`quizzes` 增列 `variant`，标记考点类型，支撑统计、覆盖审计与后续专项抽题。
- G5：提供覆盖审计，能回答「哪部法、哪个词族还没出题」。
- G6：对既有数字判断题做**去重/降相似**治理（归档重复题，不物理删除），
  并把归档能力做成可复用脚本，关系型新题同样过一遍。

### 2.2 非目标

- 不改数字判断题的出题口径；既有 1408 道题**不重新生成**，只做 §4.7 去重归档与 `variant='number'` 标记。
- 不物理删除任何题（归档即可逆）；不改动 `quiz_answers` 历史记录。
- 不改前端 UI（判断题池自动混入新题）；分类筛选/标签展示留作后续独立迭代。
- 不新增题型（不引入 `qtype='judge_rel'`），不新增题表。
- 不做主观题、案例题相关改动。

## 4. 关键设计

### 4.1 词族字典（`app/relation_terms.py` 的唯一数据源）

17 个词族，每族含「词表」+「定向互换白名单」（错题只允许在白名单内偷换）：

| 词族 | 词表 | 定向互换白名单（原文词 → 允许偷换成） |
|---|---|---|
| modal | 可以 / 应当 / 必须 / 不得 / 无须（无需） | 应当→可以、必须→可以、不得→可以、无须→应当、可以→应当 |
| authority | 有权 / 无权 / 自行决定 / 报请 / 批准 / 备案 | 自行决定→报请批准、批准→备案、有权→无权 |
| form | 决定 / 决议 / 裁定 / 判决 / 命令 | 决议→决定、判决→裁定、决定→裁定 |
| effect | 撤销 / 撤回 / 解除 / 终止 / 无效 / 可撤销 / 效力待定 / 不成立 | 撤销→撤回、解除→终止、无效→可撤销、效力待定→不成立 |
| review | 复议 / 复核 | 复核→复议、复议→复核 |
| instance | 一审 / 二审 / 再审 / 重审 / 发回重审 / 提审 / 申诉 / 申请再审 / 上诉 / 抗诉 | 一审→二审、二审→一审、再审→重审、发回重审→提审、抗诉→上诉 |
| org | 独任 / 合议庭 / 审判委员会 / 法官会议 | 合议庭→独任、独任→合议庭、审判委员会→合议庭 |
| claim | 反诉 / 反驳 / 抗辩 / 本证 / 反证 | 反诉→抗诉、抗诉→反诉、本证→反证 |
| outcome | 撤回起诉 / 撤诉 / 按撤诉处理 / 驳回起诉 / 驳回诉讼请求 / 不予受理 / 中止 / 终结 / 延期审理 | 驳回起诉→驳回诉讼请求、驳回起诉→不予受理、中止→终结、撤回起诉→驳回起诉 |

| sentence | 假释 / 减刑 / 缓刑 / 暂予监外执行 | 假释→减刑、缓刑→假释、暂予监外执行→假释 |
| time | 诉讼时效 / 除斥期间 / 上诉期 / 抗诉期 / 举证期限 / 追诉时效 | 诉讼时效→除斥期间、上诉期→抗诉期 |
| liability | 连带 / 按份 / 补充责任 / 定金 / 订金 / 违约金 | 连带→按份、连带→补充责任、定金→订金 |
| agency | 善意取得 / 表见代理 / 无权代理 / 无权处分 / 推定 / 视为 | 善意取得→表见代理、无权代理→无权处分、推定→视为 |
| evidence | 排除合理怀疑 / 高度盖然性 / 优势证据 / 举证责任倒置 / 非法证据排除 / 瑕疵证据 | 高度盖然性→排除合理怀疑、非法证据排除→瑕疵证据 |

设计约束：

- 词表是**数据**不是逻辑：新增词族只改这一处常量，不触碰出题与校验代码。
- 长词优先匹配：先匹配「发回重审」「驳回诉讼请求」「上一级」等多字词，再匹配「重审」「驳回」「上级」，
  避免子串误判。
- 白名单只约束**错题**；对题不做偷换，只做「不得新增」校验。

### 4.2 闸门规则（`app/relation_terms.py`）

`extract(text) -> set[(family, term)]`，然后：

1. **对题**：`extra = terms(stem) - terms(reference)` 必须为空——
   题干里不允许出现依据原文没有的关系词（拦住「可以 ↔ 应当」这类偷换）。
2. **错题**：`extra` 必须**恰好 1 个词** `w`，且原文中存在被替换词 `t`，满足：
   - `(t, w)` 在对应词族的白名单内；
   - `terms(reference) - terms(stem) == {t}`（保证**只**改了这一处，其余关系词完整保留）。
3. **区分性要求**：题干至少命中 1 个「区分性词族」（即 17 族中任意一族），
   只有「的/和/或者」这类非考点词不算。
4. **主体一致性**：题干中的机关/主体名（`…人民法院` / `…人民检察院` / `…公安机关` /
   `…委员会` / `…人民政府` / `…董事会` / `…股东会` 等）必须能在依据原文命中；
   或与原文主体构成「同体系表述」（如「上一级人民法院」↔「人民法院」）才放行。
5. **与数字题互不重叠但复用校验**：关系型题干若含数字表达，仍必须同时通过
   `number_terms.is_grounded(stem, reference, answer)`；否则丢弃。
6. **题干形态**：15~40 字，一句话陈述句，不得整句抄原文（相似度阈值 ≥0.85 判定为抄袭，丢弃）。

### 4.3 出题通道（`scripts/build_relation_judge.py`）

`build_judge_bank.py` 已 445 行（硬上限 500），新逻辑**不塞进旧脚本**：

| 文件 | 职责 | 预估行数 |
|---|---|---|
| `app/relation_terms.py` | 词族字典 + 抽取 + 闸门 | ≈260 |
| `scripts/build_relation_judge.py` | 候选枚举 + 生成 + 入库 + 覆盖统计 | ≈330 |
| `tests/test_relation_terms.py` | 闸门单元测试 | — |

候选枚举：

- `--source statutes`：扫描法条库，对每个含关系词的条文取命中词族（按稀有度优先，
  默认每条文最多 2 族，`--max-per-article` 可放开到全展开）；已出过的 `(basis, variant)` 跳过。
- `--source entries`：逐条取 `point/anchor/conclusion`，已出过的 `entry_id` 跳过。
- `--source counterparts`：复用现有「配对补错题」思路，为只有对题的法条/条目补错题，配平答案分布。

生成与入库：

- 复用 `app.ai.call_llm` + `quiz_bank.save_question`（`qtype='judge'`，`origin='judge'`，`status='draft'`）。
- 新参数 `variant` 落入 `quizzes.variant`。
- **幂等断点续跑**：同一 `(basis, variant, answer)` 或 `(entry_id, variant, answer)` 已存在则跳过，
  中断后重跑不重复计费、不重复入库。

### 4.4 数据模型（`quizzes.variant`）

`quizzes` 增列 + 扩展 `status` 取值（沿用 `db.connect()` 幂等重建 + 旧库备份到
`data/backup/` 的既有机制，同一次重建完成，避免两次迁移）：

| 列 | 类型 | 含义 |
|---|---|---|
| `variant` | TEXT NOT NULL DEFAULT '' | 数字题 `number`；关系题取 17 个词族名之一（`modal`/`form`/`instance`…） |
| `status` | 取值扩展为 `draft` / `published` / **`archived`** | `archived`＝下架题：不进抽题池，但保留行与历史答题关联 |

回填：`UPDATE quizzes SET variant='number' WHERE origin='judge' AND variant=''`（升级时执行一次）。
`qtype`、`origin` 的 CHECK 约束不变。

配套改动（防归档题复活）：

- `quiz_bank.pick` 已按 `status='published'` 过滤，归档题自动出池，无需改动。
- `quiz_bank.set_status`（`--publish` 走它）加 `AND status != 'archived'`，
  避免批量发布把归档题重新拉回抽题池。

### 4.5 抽题与混排

`app/quiz_service.py::judge_quiz` 与 `quiz_bank.pick` **无需改动**：
判断题池按 `origin='judge' + qtype='judge' + status='published'` 抽取，新题自动混入。
后续要做「只练关系题 / 只练数字题」时，再加 `variant` 过滤参数即可（本次不做）。

### 4.6 覆盖审计

新增 `scripts/audit_relation_coverage.py`（不塞进已有 157 行的 `audit_quiz_coverage.py`）：

- 法条侧：已出题的条文数 / 含关系词条文数；按法、按词族两个维度输出缺口清单。
- 条目侧：已出题条目数 / 1,309 条含关系词条目。
- 输出报告 `docs/superpowers/research/2026-09-21-关系型判断题覆盖报告.md`。

### 4.7 数字判断题去重/降相似（G6）

对现有 1408 道数字判断题做一次可复现治理，默认 `--dry-run`，`--apply` 才写库；
动作统一是 `status='archived'`（可逆：改回 `published` 即恢复）。四条规则按序执行，
每族只保留信息量最大的一题（`analysis` 更长者优先，其次有 `basis` 者优先）：

| 规则 | 判据 | 实测归档 |
|---|---|---|
| R1 完全重复 | 题干 + 答案完全相同 | 3 |
| R2 同源近似 | 同 `basis` + 同答案，题干相似度 ≥0.75 | 23 |
| R3 同法模板化 | 同法（`basis` 去条号）+ 数字占位化后题干相同 **且同答案** | 0 |
| R4 同源超额 | 同 `basis` + 同答案超过 1 题 | 93 |
| **合计** | | **119（7.3%）**，剩余 1510 题（对 820 / 错 690） |

说明：R3 只收缩「同一部法内、把数字抹掉后逐字相同」的模板题（如某公约重复出现的
签署/生效句式）。不同法但同句式的题（如两部公约各自的签字截止日）属不同考点，保留。
R3 必须带「同答案」维度：数字抹平后，「对」题与「错」题天然同句，不带答案维度会把
合法的「对/错」配对题误归档（实测会多归档 87 道配对题）。
关系型新题生成后复用同一脚本（`--origin judge --variant-any`）做同样治理。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| LLM 换词方向错、编造关系词 | §4.2 闸门硬拦（对题禁新增、错题限白名单单点） |
| 词表不全导致漏判（如某法特有的「核准」） | 词表为单一数据源，审计报告暴露漏判后可增补，不改逻辑 |
| 主体被偷换（「上级法院」→「本院」） | 主体一致性校验 + 抽检 |
| 生成量大致中途中断 | `--only-missing` 幂等续跑，分批执行 |
| 同一条文多题雷同 | 每条文 ≤2 族 + `text_hash` 去重 + 抽检 |
| 判题分布失衡（对题过多） | `--source counterparts` 补错题配对 |
| 与数字题重复出同一考点 | 关系题题干若含数字，仍过 `number_terms.is_grounded` 校验；审计报告比对 |
| 归档误伤（把不同考点当重复归档） | 默认 `--dry-run` 先看清单；归档可逆（改回 `published`），不物理删除 |
| 迁移重建损坏题库 | 沿用既有重建机制（先备份 `data/backup/`），`tests/test_db.py` 覆盖迁移用例；重建后核对题量 |

前端筛选/标签、专项练习入口不在本次范围（后续独立 Spec）。

## 10. 头脑风暴：易混词族全景（实施顺序按原料量）

**第一梯队（原料最多、最像真题陷阱）**：modal（可以/应当/必须/不得/无须）、form（决定/决议/裁定/判决）、
effect（撤销/撤回/解除/无效）、review（复议/复核）。

**第二梯队（程序与层级）**：instance（一审/二审/再审/重审/发回重审/提审/上诉/抗诉）、
org（独任/合议庭/审判委员会）、claim（反诉/反驳/抗辩/本证/反证）、
outcome（撤回起诉/驳回起诉/驳回诉讼请求/不予受理/中止/终结）。

**第三梯队（主体与层级管辖）**：level（本级/上一级/上级/同级/省级/设区的市级/县级）、
authority（有权/无权/自行决定/报请/批准/备案）。

**第四梯队（实体概念对，语义核验成本高，全部走闸门 + 抽检）**：
sanction（罚金/罚款、吊销/注销、没收财产/没收违法所得）、
coercion（取保候审/监视居住/逮捕/拘传/留置）、sentence（假释/减刑/缓刑/暂予监外执行）、
time（诉讼时效/除斥期间/上诉期/抗诉期/举证期限/追诉时效）、
liability（连带/按份/补充责任、定金/订金、违约金）、
agency（善意取得/表见代理/无权代理/无权处分、推定/视为）、
evidence（排除合理怀疑/高度盖然性/优势证据、非法证据排除/瑕疵证据）。

四个梯队**全部纳入本次覆盖**（不做小批量试产），实施顺序按上表批次推进。

## 11. 实测结果（2026-09-20 执行）

| 项 | 结果 |
|---|---|
| 关系型判断题发布 | **23,737 条**（对 13,012 / 错 10,725；17 个词族全有题） |
| 提问次数 | 法条侧 4 轮、条目侧 3 轮、配对补错题 6 轮，合计约 5.9 万次调用 |
| 单轮闸门通过率 | 法条侧 57%~63%、条目侧 31%~63%；错题配对经提示词改造后 11% → **77%** |
| 判断题全池 | **25,247 条 published**（数字型 1,510 + 关系型 23,737） |
| 法条侧覆盖 | 9,846 / 12,159 含关系词条文 = **81.0%** |
| 条目侧覆盖 | 796 / 1,293 含关系词条目 = **61.6%** |
| 回源复核 | 法条侧 22,622/22,724、条目侧 1,115/1,118；不通过者已归档（复核口径见下） |
| 去重/归档 | 数字题 119 条 + 关系题约 1,400 条（重复、模板句、回源不通过），全部可逆 |
| 数字题去重残留 | published 1,510（对 820 / 错 690），`quiz_answers` 历史未动 |

**错题配对的关键改造**：把「让模型自己挑偷换」改成「逐字照抄原文、只改指定的那一处
（`_pick_swap` 按 basis 稳定轮换）」，并把依据收缩到含目标词的单句（`_sentence_with`），
通过率 11% → 77%，对/错 从 1.8:1 收敛到 1.2:1。

尚未覆盖的 19.0%（法条侧）/ 38.4%（条目侧）主要是闸门丢弃后未重试的候选；
直接重跑即可补齐（幂等、只补缺口）：

```bash
cd backend
.venv/bin/python scripts/build_relation_judge.py --source statutes --workers 8   # 再跑 1~2 轮
.venv/bin/python scripts/build_relation_judge.py --source counterparts --workers 8
.venv/bin/python scripts/dedupe_judge_bank.py --apply
.venv/bin/python scripts/audit_relation_coverage.py --verify --archive-failed --report ../docs/superpowers/research/2026-09-21-关系型判断题覆盖报告.md
.venv/bin/python scripts/build_relation_judge.py --publish
```

已知遗留（本次未处理，建议单独排期）：

1. **条号口径错位**：部分公约/司法解释类文件里「文件内第X条」与「法条库索引第X条」内容不一致
   （实测 1,785 条），影响 basis 跳转精度；`audit_relation_coverage.py --verify` 已能统计。
2. **对/错仍未 1:1**：1.21:1（13,012:10,725），靠多轮 `--source counterparts` 继续收敛。
3. 关系题只校验「关系词 + 数字」，题干里其余修饰语仍可能与原文有细微出入（抽检可见）。
4. **复核口径**：错题出题时依据收缩到单句，复核按同一口径判定（`audit_relation_coverage.check_question`），
   不能用「原文只少一个关系词」的全文判据，否则会把合法错题误判为不通过。
