# Spec：优化自测、看背、听学与 AI 展示

- 日期：2026-09-01
- 状态：待评审
- 涉及模块：
  - frontend: QuizView, GroupQuizView, FlashcardView, ListenView, AiChat, md.ts, progressStore.ts, types.ts, components.css
  - backend: service.py, quiz_service.py, routers/quizzes.py, routers/plans.py, routers/reviews.py, review_stats.py, ai.py

## 1. 问题背景

用户反馈 5 点核心体验问题：

1. **自测一键生成**：当前点击「自测」直接生成题目，用户期望有更多控制（如选择题量、模式、范围），而非直接进入做题。
2. **自测不可回看**：QuizView 和 GroupQuizView 只有「下一题」，无「上一题」按钮，答完即不可回退查看解析。
3. **AI 回答 markdown 原样显示**：AiChat 组件直接用 `white-space: pre-wrap` 渲染流式文本，`**加粗**`、`*斜体*`、`代码` 等 markdown 标记原样可见。
4. **看背自定义范围不记录进度**：在「自定义范围」模式下看背，评分记录虽写入 reviews，但 `reviewedToday` 只统计今日计划内条目；刷新后进度丢失，显示「今日卡片已看完」。
5. **自定义范围优先级未优化**：看背/听学自定义范围的排序未按「未读/未听优先 → 读/听次数少优先」，现为优先级×科目顺序。

## 2. 方案概要

### 2.1 自测入口与控制（前端 QuizView + GroupQuizView）

- **QuizView（今日自测）**：保持现有每日自动生成 10 题，但新增「重新生成」按钮（调用 `/api/quiz/today?regenerate=1` 或直接重新拉取）。
- **GroupQuizView（智能组卷）**：已有自定义范围、题量、限时选择，保留并优化。
- **新增「上一题」**：QuizView 与 GroupQuizView 均在题目卡片底部增加「上一题」按钮（`idx > 0` 时启用），点击可回退查看已作答题目的解析，不重新提交答案。

### 2.2 AI 聊天 markdown 渲染（前端 AiChat + md.ts）

- AiChat 的 `chat-bubble` 当前用 `white-space: pre-wrap` 直接显示纯文本。
- 方案：AI 流式输出累积的文本在渲染前经过 `mdToHtml` 转义+渲染，保留 `pre-wrap` 的换行行为。
- 实现：在 `messages` 状态存原始文本，渲染时 `dangerouslySetInnerHTML={{ __html: mdToHtml(m.text) }}`；用户气泡保持纯文本。
- 需确保 `mdToHtml` 对代码块、表格等复杂结构的容错（现有实现已支持基础语法）。

### 2.3 看背自定义范围进度持久化（前端 FlashcardView + progressStore）

- 问题根因：`reviewedToday` 初始化仅来自 `plan_payload`（今日计划），自定义范围条目不在其中。
- 方案：
  1. `applyCustom` 加载自定义范围条目后，立即并行请求 `/api/reviews/history?mode=read&limit=500`，提取今天已看过的 `entry_id` 合并入 `reviewedToday`。
  2. `rate()` 评分成功后，`reviewedToday.add(entry.id)` 已有，保留。
  3. `loadMore` 追加条目时，同样合并新条目的 `reviewed_today` 字段。
  4. `progressStore` 的 `READ_STORE_KEY` 已持久化 `ids` 与 `idx`，刷新恢复时 `restoreQueue` 已处理，无需改动。

### 2.4 听学自定义范围进度持久化（前端 ListenView）

- 同理：`applyCustom` 加载后并行拉取今日听学记录，合并入 `heardTotal` 与队列项的 `listen_count`/`last_ts`（后端 `custom_entries(listen_only=True)` 已附带 `attach_listen_counts`）。
- `loadMore` 追加时同样合并。

### 2.5 自定义范围排序优化（后端 service.py）

- **看背 `custom_entries(listen_only=False)`**：
  - 现状：按 `priority_order, subject_order, id` 排序。
  - 目标：`read_count=0` 优先 → `read_count` 升序 → priority → subject → id。
  - 实现：SQL 先按 `read_count` 聚合，或在 Python 排序 key 中加入 `read_count`。

- **听学 `_listen_pool` / `custom_entries(listen_only=True)`**：
  - 现状：未听过优先，已听按最近听过倒序。
  - 目标：`listen_count=0` 优先 → `listen_count` 升序 → 最近听过越久越优先（`last_ts` 升序） → priority → subject → id。
  - 实现：调整 `never` / `heard` 分组与排序 key。

## 3. 数据模型变更

无表结构变更。仅调整查询排序与前端状态初始化逻辑。

## 4. API 变更

### `GET /api/quiz/today`
- 新增可选查询参数 `regenerate=1`：强制重新生成今日题目（删除当日 quizzes 缓存后重建）。前端「重新生成」按钮调用。

### `GET /api/reviews/history`
- 已支持 `mode=read|listen`，前端自定义范围加载后并行调用，无需改动。

### `POST /api/plans/custom` / `POST /api/listen/custom`
- 响应体 `items` 已含 `read_count` / `listen_count` / `last_ts` / `reviewed_today`（后端 `attach_read_counts` / `attach_listen_counts` / `attach_reviewed_today` 已实现）。
- 排序逻辑在 `service.custom_entries` 与 `_listen_pool` 中调整。

## 5. 验证标准

1. **自测**：
   - QuizView 今日自测页有「重新生成」按钮，点击后题目刷新。
   - QuizView 与 GroupQuizView 均有「上一题」按钮（非首题时），可回退查看已作答题目解析，不重新提交。

2. **AI markdown**：
   - AI 回答中的 `**加粗**`、`*斜体*`、`` `代码` ``、`- 列表`、`| 表格 |` 正确渲染为 HTML；用户气泡保持纯文本。

3. **看背自定义范围进度**：
   - 进入自定义范围 → 看完 3 条并评分 → 刷新页面 → 进度恢复，`reviewedToday` 显示 3，卡片显示「今日已看」。

4. **听学自定义范围进度**：
   - 同理，听完 2 段 → 刷新 → 队列位置恢复，`heardTotal` 与 `listen_count` 正确。

5. **自定义范围排序**：
   - 看背：未读条目排在前，读过 1 次的在读过 3 次的前面。
   - 听学：未听条目排在前，听过 1 次的在听过 3 次的前面；同次数下，更久未听的排前。

6. **回归测试**：
   - `pytest tests` 全绿（现有 125+ 用例）。
   - Playwright 截图回归：自测上一题、AI markdown、看背/听学自定义范围刷新恢复、排序顺序。

## 6. 范围边界

- 不做：AI 对话历史持久化、题库重生成策略调整、样式系统重构。
- 不改：`qtype` CHECK 约束、reviews 表结构、进度存储键名。
