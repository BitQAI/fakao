# 法条题卡「30 秒朗读文本」与全量音频生成 — Spec（2026-09-20）

## 1. 用户决策

1. 听学单条卡片音频**必须 ≤30 秒**（此前卡片平均 450 字 ≈ 95 秒）。
2. 手段是**简化朗读文本到 30 秒的字数**，不是截断：文本要读得通、语义完整。
3. 之后**为全部法条题卡生成音频与 `tts_assets` 台账**（12052 张）。

## 2. 现状

| 项目 | 数值 |
|---|---|
| 卡片朗读文本 | 平均 450 字，最长 1055 字 → 实际音频 90~115 秒 |
| 组成 | 依据 → 条文原文(≤160) → 题干(中位 93) → 选项(中位 108) → 答案 → 解析(中位 87) |
| 实测语速 | 中位 4.79 字/秒（p25 4.58，慢样本 3.13） |
| 30 秒对应字数 | 约 140 字（中位语速），保守按 4.5 字/秒 ≈ 135 字 |

## 3. 方案

### 3.1 朗读文本（`statute_cards.listen_text`）

新组成，按信息价值排序，**丢弃「选项」与「条文原文」**（选项在听感上冗余，答案已给出；
条文原文可长可短且与解析重复，用户可在卡片背面看）：

```
法条依据：<basis>。
题目：<题干（按预算裁剪，句读优先）>
答案：<answer>。
解析：<解析首句（按预算裁剪）>
```

- 上限常量 `LISTEN_MAX_CHARS = 110`（归一后字数口径），实测标定后再定稿；
- 预算分配：固定部分（依据/答案/标签）先扣，剩余约 **62% 给题干、38% 给解析**；
  某一部分用不满额度时，剩余额度让给另一部分；
- 裁剪在句读边界（。；，）优先，找不到边界则断句补「。」，**绝不出现半句英文/未闭合标点**；
- 函数保持确定性：同一道题永远得到同一段文本（同步脚本幂等，不会反复作废音频）。

### 3.2 同步与音频失效

- `sync_card_entries.py` 重跑会把 12052 张卡片的 `tts_text` 换新版；
  `_drop_audio()` 会自动删除旧 wav 与旧台账行（现有机制，无需新增逻辑）——
  本轮已预热的 209 张会被作废，属预期。

### 3.3 全量生成（含 ≤30 秒硬校验）

- 用既有 `synthesize_cards.py --all --shard I/N --workers W` 分片并行（多 agent 各一片）。
- 生成后跑 `audit_tts.py --kind card`：**新增 30 秒口径检查**（`duration_sec > 30` 归入
  `over_length`，进 `repair_ids`），超时卡片由 `repair_tts.py --kind card` 返工。
- 返工若仍超时，说明该题文本预算偏大 → 由 `LISTEN_MAX_CHARS` 统一收紧后再同步（不做逐条特例）。

## 4. 验证标准

1. 抽样 ≥20 张：`normalize(tts_text)` 字数 ≤110，音频时长 ≤30 秒，且文本含依据/答案。
2. 全量生成后：卡片有音频数 = 12052，`tts_assets` = 12052，`over_length` = 0。
3. `pytest tests` 全绿。
4. 磁盘占用估算：30 秒 ≈1.4 MB/张 → 全量约 **17 GB**（可用 50 GB，放得下）。

## 5. 范围边界

- 只改**卡片**朗读文本；正式条目（2426 条，平均 67 字 ≈14 秒）不动。
- 看背/自测/法条页展示的题干、选项、条文原文全部不变，只影响听学朗读文本。
- 不做逐条人工润色；文本全部由确定性规则生成。
