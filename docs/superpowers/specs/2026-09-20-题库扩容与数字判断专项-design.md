# 题库扩容、数字判断题入口与 TTS 质检修复 — Spec（2026-09-20）

## 1. 问题背景

用户提出四项需求：

1. 依据**新增的法条法本、司法解释与考点要求**，尽量完善丰富**客观题题库**与**主观题题库**。
2. 优化原有 **TTS 录音与朗读文本**，有问题的删除后重新生成。
3. 在合适位置增加**数量 / 金额 / 年限 / 人数**等「数相关」**判断题入口**。
4. 若当前 API key 的 TTS 模型全部不可用，再考虑换用备用 key。

## 3. 目标与非目标

### 3.1 目标

- G1：客观题从「按天懒生成」升级为**持久题库**，题量覆盖全部 final 条目，且自测/组卷优先用库内题、LLM 仅兜底。
- G2：新增**数字判断题（judge）**题型与独立入口，原料来自法条库数字条文 + 条目的数字型结论。
- G3：主观题题库扩容，优先消化案例库中带「争议焦点」的案例，并补齐新法专题。
- G4：TTS 建立**质检 + 台账 + 可重生成**闭环，坏录音被替换，朗读文本规范化。
- G5：TTS 增加备用 key 降级通道（仅 `.env`，不进代码）。

### 3.2 非目标

- 不改条目生成流水线的字段结构（沿用 `fakao-entry/1.0`）。
- 不引入 FSRS/间隔重复算法。
- 不做主观题自动判分（沿用「采分点勾选」口径，LLM 不评判用户文字）。
- 不做整卷模考与计时成绩换算。

## 4. 方案

### 4.1 数据模型：题库并入 `quizzes`，不新增并行题表

理由：错题本、做题历史、复盘统计全部通过 `quiz_answers.quiz_id → quizzes.id` 关联；
若另建题表，这些能力需要全部重写。

`quizzes` 增列（幂等迁移，SQLite 重建表以放宽 CHECK）：

| 列 | 含义 |
|---|---|
| `origin` | `daily`（当日缓存，沿用现逻辑）/ `bank`（客观题库）/ `judge`（数字判断题） |
| `basis` | 法条依据（如「刑诉法第192条」），可空 |
| `status` | `draft` / `published`，未发布题不进入抽题池 |
| `text_hash` | 题干+答案指纹，用于幂等重生成 |

`qtype` 取值扩展为 `choice` / `cloze` / `judge`；`judge` 的 `answer ∈ {对, 错}`，`options=[]`。

新增 `tts_assets` 表（TTS 台账）：`entry_id, text_hash, bytes, duration_sec, created_at`。

### 4.2 客观题题库（`scripts/build_quiz_bank.py`）

- 上游：`entries`（final）。每条出 1 题，单选为主、约 1/3 多选，干扰项来自同 submodule 的易混条目。
- 出题口径沿用 `ai.generate_quiz` 的既有约束（题干用 anchor 场景、正确项来自 conclusion、30–60 字解析），新增 `basis` 与 `submodule` 回填。
- 幂等：`(entry_id, origin='bank')` 已存在且 `text_hash` 未变则跳过；支持 `--only-missing`、`--subject`、`--priority`、`--limit`、`--workers`、`--publish`。
- 入库为 `draft`，人工抽检后 `--publish` 转 `published`（沿用主观题题库口径）。

### 4.3 数字判断题（judge）

- 原料 A（法条）：扫描 `data/法条库`，抽取含「数量/金额/年限/人数/期限/比例」表达的条文，按（法名 × 数值类型）聚类取样，LLM 生成「判断句 + 对错 + 修正说明 + 依据条号」。
- 原料 B（条目）：`entries` 中 conclusion 含数字表达的 1079 条，抽取核心数字考点出题。
- 难度控制：错误项由**单位/主体/期限/比例**四类扰动之一构造，且必须在解析中说明正确值。
- 存储：`quizzes.origin='judge'`，`qtype='judge'`。

### 4.4 主观题题库扩容

- 案例题：优先从「含争议焦点」的 1752 条案例中按科目配比扩至 40 题（现 12）。
- 综合大案例：扩至 12（现 5）。
- 论述题：扩至 25（现 21），补齐新法与时政专题。
- 复用 `build_case_questions.py` / `build_composite_questions.py` / `build_essay_questions.py`，只增加选源参数与发布开关。

### 4.5 TTS 质检与修复

- 新增 `app/tts_text.py`：`normalize()` 做**确定性安全替换**（去 Markdown、符号→中文词、连续空白归一、法条号规范），不改写语义；可选 `--llm-rewrite` 做语义顺读化。
- 新增 `scripts/audit_tts.py`：输出「缺失 / 空文件 / 陈旧（hash 不符）/ 时长异常（<3.5 或 >6.5 字/秒）/ 台账缺失」五类清单，并生成质检报告。
- 新增 `scripts/repair_tts.py`：对异常与陈旧条目先删 wav 再调用 `tts.ensure_mp3` 重合成，`--dry-run` 默认、`--apply` 才写入；只重生成受影响条目。
- `tts.py` 主 key 全模型失败时，回退 `DASHSCOPE_API_KEY_FALLBACK`（仅存 `.env`）。

### 4.6 前端入口

- 自测页（`/study?view=quiz`）子页签由「今日 / 组卷 / 历史」扩展为「今日 / 组卷 / 数判 / 历史」。
- `数判`：选科目/知识点 + 题量（默认 10），逐题「对 / 错」两键作答，答完立即给解析与法条依据；错题进入错题本与历史（复用现有链路）。
- 今日自测优先从 `origin='bank'` 取题，题库无题时回退现生成，用户无感。

## 5. 验证标准

1. `backend/tests` 全绿（现有 233 项 + 新增题库/判断题/迁移测试）。
2. 题库抽样：`origin='bank'` 抽查 20 题，题干/选项/答案/解析/依据五要素齐全，答案字母合法。
3. 判断题抽样：随机 20 题，正确值与法条原文一致（脚本自动核对「正确值在条文中出现」）。
4. TTS：4 条已知截断录音重合成后时长回归正常区间；`audit_tts.py` 复测异常数为 0（或全部有解释）。
5. 前端：Playwright 实机验证「数判」入口 → 作答 → 解析 → 错题本闭环，控制台 0 错误。
6. `python -m pytest`、`npm run build`/`tsc --noEmit` 无告警。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 批量 LLM 出题费用与耗时 | 分阶段跑、支持 `--limit` 断点续跑；先小批量抽检再全量 |
| LLM 出题与法条原文不符 | 判断题强制「正确值必须出现在所引条文中」，脚本硬校验，不符即丢弃 |
| 重建 `quizzes` 表丢数据 | 迁移前备份 `quizzes`/`quiz_answers` 到 `data/backup/`；迁移幂等可重入 |
| 全量重合成音频耗时长（2426 条 × ~2s） | 只重生成异常/陈旧条目；全量重生成作为可选命令 |
| 题干与旧缓存题重复 | `text_hash` + `(entry_id, origin)` 唯一约束 |

## 7. 范围边界

- 本轮不新增科目、不改八科口径。
- 本轮不改条目 JSON 结构，不动 `data/entries/*.json` 既有条目。
- 本轮不做真题整卷还原（回忆稿仅作考点校准输入）。
