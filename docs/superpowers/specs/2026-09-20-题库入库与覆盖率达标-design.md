# 题库进版本库与法条覆盖率达标 — Spec（2026-09-20）

## 1. 背景与用户要求

1. **题库要像 `data/entries/*.json` 一样进版本库**：现在 9000+ 道题只存在于
   `data/fakao.db`（gitignore），换机器/回滚/协作都无法带走，也看不出「这轮加了什么题」。
2. **法条覆盖率至少 80%**：当前 7006/15958 = 43.9%，还有 ~8900 条条文没有题目覆盖。

## 2. 方案概要

### 2.1 题库入库（导出 / 导入）

- 新增 `scripts/export_quiz_bank.py`：把 `quizzes` 表按「origin + subject」导出成
  `data/quiz_bank/<origin>-<科目>.json`，与 `data/entries/*.json` 同风格的版本库资产。
- 新增 `scripts/import_quiz_bank.py`：读 JSON 幂等写回 `quizzes`，供新机器/回滚后重建题库。
- 只导出 **published**：draft 是生成中间态（可能正在被脚本使用），archived 是下架题，
  两者都不进版本库；需要时可 `--status draft,archived` 显式导出。
- `daily` origin 是「当日缓存题」，可由用户行为重新生成，不入库。

**文件格式**（每文件一个 JSON 对象）：

```json
{
  "schema": "fakao-quiz-bank/1.0",
  "origin": "bank",
  "subject": "刑法",
  "exported_at": "2026-09-20",
  "count": 670,
  "items": [
    {"entry_id": "XF-001", "point": "追诉时效", "qtype": "choice",
     "stem": "…", "options": ["A. …", "B. …"], "answer": "A",
     "analysis": "…", "basis": "中华人民共和国刑法第八十七条", "variant": ""}
  ]
}
```

**排序**：按 `(entry_id 或 "", basis, stem)` 升序，保证同内容重复导出时 diff 稳定（近似追加）。

**幂等键**：复用 `quiz_bank.save_question()` 的既有键
`(origin, qtype, entry_id 或 text_hash, answer)`；`replace=False`，导入不会覆盖库中已有的同题。

### 2.2 覆盖率达标 80%

- `scripts/build_statute_quiz.py` 增 `--target-ratio R`：按每部法**反推缺口**
  （`需要 = ceil(R × 该法条数) − 已覆盖条数`），只补缺口条文，而不是每部法统一配额。
  统一配额在大法典上永远追不上（民法典 1260 条、生态环境法典 1242 条）。
- 候选排序沿用「数字/要件型条文优先」（`_score_article`），与判断题同一套打分。
- 每轮跑完 `--publish`，用 `audit_quiz_coverage.py` 复测；未达标就再跑一轮
  （失败题不占坑，下一轮会重新取到，天然可续跑）。

## 3. 非目标

- 不把 9000+ 道题做人工全量校对（沿用脚本质检 + 抽检）。
- 不为「无条号结构」的文件伪造条号（如《刑诉法第292条解释》），这类缺口单列。
- 不导出 `daily` 缓存题、不导出做题记录 `quiz_answers`。
- 不改 `quizzes` 表结构。

## 4. 验证标准

1. `export → import` 往返：新建空库导入后，题目数与源库 published 数一致、抽样内容一致。
2. 重复导入幂等：第二次导入 `quizzes` 行数不变。
3. `audit_quiz_coverage.py` 总覆盖率 **≥80%**，且报告里的「strict 不通过」保持 0。
4. `pytest` 全绿；前端无改动则只跑 `tsc`；组卷/数判接口抽测正常。

## 5. 风险

| 风险 | 对策 |
|---|---|
| 导出文件大、diff 噪音 | 按 origin+科目切分（≤16 个文件），稳定排序 |
| 导入把人工改过的题覆盖掉 | `replace=False`，同题只跳过不覆盖；`--replace` 显式开启 |
| 8 万次 LLM 调用费用/耗时 | `--target-ratio` 精确定位缺口；可随时中断续跑；失败题不重复计费（未入库） |
| 覆盖率上去了但题目质量下降 | 沿用现质检闸门（结构 + 正确项与条文相关 + 不照抄条文），audit 复核 |
