# 案例库分面筛选与浏览 — Spec（2026-09-22 增补）

## 1. 需求

上一版案例库只能「输关键词→看结果」。实际用法是**不输入任何关键词也要能看**：

1. 按部门法浏览：刑事 / 民事 / 行政 / 国家赔偿 / 执行；
2. 按罪名浏览：故意杀人罪、故意伤害罪、诈骗罪、受贿罪、盗窃罪…；
3. 按年份（案例日期年度）筛选与排序；
4. 组合筛选（部门法 + 罪名 + 年份 + 来源库），并给出命中总数与分页。

## 2. 数据依据（2026-09-22 实测 7172 篇）

| 维度 | 数据来源 | 实测分布 |
|---|---|---|
| 部门法 | `cases.keywords[0]` | 刑事 2645 / 民事 2555 / 行政 1035 / 执行 577 / 未标注 303 / 国家赔偿 57 |
| 罪名 | `cases.keywords` 中以「罪」结尾的词 | 224 种；故意伤害罪 231、诈骗罪 214、故意杀人罪 199、受贿罪 189、盗窃罪 169、抢劫罪 135… |
| 年份 | `cases.date` 前 4 位 | 1995–2026；2023 年 1847 篇最多，2021 年 1029 |
| 来源库 / 类别 | `cases.source` / `cases.category` | 人民法院 5537 / 司法部 1100 / 最高检 257 / 最高法 278 |

口径决定：

- **主部门法只认 `keywords[0]`**：130 篇关键词里出现 ≥2 个部门法标签，用「包含语义」会让计数与筛选对不上；
  且 `format_cases.py` 生成时已把部门法标签固定放在首位。
- 罪名维度采用**数据驱动**（不引入受控词表）：`keywords` 里以「罪」结尾的词，剔除
  `无罪 / 有罪 / 犯罪`，保留 `共同犯罪 / 毒品犯罪 / 不作为犯罪` 这类常用刑事主题词。
- 年份归一到 4 位数字；`date` 有点号（5533）与横线（1635）两种写法，排序前统一把 `.`、`/` 归一成 `-`。
- 「入库年限」本库没有入库时间字段（`cases` 表无 `created_at`），本版按**案例日期年度**实现；
  若将来要真正的入库时间，需加列 + 迁移。

## 3. API 变更（只读，不改表）

### 3.1 `GET /api/case/facets`（新增）

```json
{
  "total": 7172,
  "fields":  [{"value": "刑事", "n": 2645}, {"value": "民事", "n": 2555}, "..."],
  "crimes":  [{"value": "故意伤害罪", "n": 231}, "..."],
  "years":   [{"value": "2023", "n": 1847}, "..."],
  "sources": [{"value": "人民法院案例库", "n": 5537}, "..."],
  "scanned": 7172
}
```

单趟扫描 `source/category/keywords/date` 聚合（实测 17 ms），进程内**不做缓存**（数据小、无失效问题）。

### 3.2 `GET /api/case/search`（扩展）

| 参数 | 说明 |
|---|---|
| `q` | 关键词，可空；空 = 纯浏览 |
| `source` | 来源库（4 库枚举） |
| `field` | 主部门法：刑事/民事/行政/执行/国家赔偿/未标注 |
| `crime` | 罪名关键词（精确匹配 keywords 元素） |
| `year` | 4 位年份 |
| `sort` | `relevance`（默认；无 `q` 时自动退化为 `newest`）/ `newest` / `oldest` |
| `limit` / `offset` | 分页，默认 30 / 0（limit ≤ 100，offset ≥ 0） |

返回：`{items, total, offset, limit, sort, query, filters:{source,field,crime,year}}`。
`total` 是**筛选后的全量命中数**（不是当前页条数），前端据此显示「共 N 篇 / 加载更多」。

行为边界：

- 全部参数都为空 → 返回按 `sort` 排序的浏览结果（默认最新在前），**不再返回空列表**；
- `q` 非空时沿用关键词模糊检索（标题 > 案号 > 关键词 > 类别 > 正文 的权重），再叠加维度筛选；
- 筛选之间是 AND；部门法/罪名/年份都是精确匹配（不是模糊）；
- 未知 `source` → 404；未知 `sort` → 400。

## 4. 前端（布局 v2：筛选只占一行）

**首版把 4 组筛选全平铺，占掉大半屏（用户反馈），改为「一行 + 高级筛选」：**

默认只占一行的控件条 `.casebar`（高 34px，四个控件同一 y 轴）：

| 控件 | 内容 |
|---|---|
| 部门法下拉 | 全部部门法 / 刑事 2645 / 民事 2555 / 行政 1035 / 执行 577 / 国赔 57 / 未标注 303 |
| 年份下拉 | 全部年份 / 1995–2026（倒序） |
| 排序下拉 | 相关度（无关键词时标注「同最新」）/ 最新 / 最早 |
| 「高级筛选」按钮 | 展开面板；已选高级条件时显示计数（如 `高级筛选 · 1`） |

「高级筛选」面板（默认收起，展开后内联在控件条下方）：

1. **来源库** chips（全部 7172 / 人民法院 5537 / 司法部 1100 / 最高检 257 / 最高法 278）；
2. **罪名** chips：默认前 12 个热门罪名（带计数），「展开全部 223 个」；
3. 底部：`清空筛选`（无筛选时禁用）+ `收起`。

其他：

- 当前筛选摘要**并入结果计数行**（`共 17 篇（已显示 17）｜刑事 · 故意杀人罪 · 2023 年`），不额外占行；
- 结果区「加载更多」每次追加 30 条；
- 筛选状态为本地状态（不写 URL），关键词仍可通过 `?q=` 分享；
- 空态文案从「输入关键词检索」改为「选一个维度，或直接往下看」。

布局自验（Playwright，`localhost:3001`）：控件条高度 34px、四个控件 y 坐标一致、
高级面板默认不存在于 DOM；截图 `frontend/e2e/shots/40-cases-one-row.png`、`41-cases-advanced-open.png`。

## 5. 验证标准

1. `tests/test_case_facets.py`：标签/罪名/年份/来源计数与实测一致；部门法计数之和 = 总数（未标注计入）。
2. `tests/test_case_index.py` 扩展：field / crime / year 过滤、组合 AND、`newest`/`oldest` 排序、
   `offset`+`limit` 分页、`total` 为全量命中数、空 `q` 返回浏览列表。
3. `tests/test_api_case_library.py` 扩展：facets 接口、非法 sort 400、未知 source 404、分页参数边界。
4. Playwright：点「刑事」→ 结果与计数变化；点「故意杀人罪」→ 命中数 >0；年份选 2023 → 列表更新；
   切「最早」→ 首条年份 ≤ 末条；「加载更多」条数增加；console 无错误。

## 6. 范围边界

- 不改 `cases` 表结构、不加索引、不引入新依赖；
- 不做司法部子类别（`category` 有 30+ 种）筛选、不做向量/语义检索、不做收藏与朗读；
- 筛选状态不进 URL（分享链接只保留关键词），后续要做再加。
