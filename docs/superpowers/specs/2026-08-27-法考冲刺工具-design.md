## 一、产品定位与成功标准

**一句话定位**：17 天冲刺用的个人 AI 法考教练——基于已清洗好的客观题条目库，每天动态倒排「今天学什么」，通过看背、听学、自测三种方式过内容，AI 早晚复盘调整计划。

**用户背景**：去年考过一次、复习过一轮；重难点与资料库已备好，尚未开始复习；距离考试 17 天，节奏紧。

**成功标准**：AI 每天根据「剩余天数 × 每日容量 × 条目总量」自动算配比，动态权衡覆盖与重复，保证每天执行的是当前最优学习组合。

**使用节奏**：白天工作期间长时间听学浸泡；早 1 小时、午 1 小时、晚 4 小时整块看/背。

| LLM | DeepSeek，key 存服务器 `.env`，服务端调用 |
| 复习调度 | 简化三级调度 + 全量复习历史落库，预留 FSRS 升级 |
| 复盘 | 早报（今日计划）+ 晚报（今日总结与明日调整） |
| 覆盖视图 | 树状图（科目→子科目→考点）；不做点图谱 |
| 自测 | 内嵌每日 10 题，非独立大模块 |
| 导航 | 4 Tab：今日 / 学习 / 报告 / 我的 |
| AI 助手 | 全局悬浮入口 + 看背卡片内快捷提问，RAG-lite 带出处 |
| 条目字段 | 12+1 可选字段：在 12 字段基础上增加 `cases`（案例原文，0–3 条，填了必须存在于统一索引） |

### 2.1 数据分层与清洗策略

| 数据 | 规模 | 定位 |
|---|---|---|
| `data/科目资料/7科/`（22 份 md） | 约 8400 行 | **条目库唯一生产来源**；AI 抽取候选 → 12 字段 draft 条目 |
| `data/案例数据/`（人民法院案例库 / 司法部 / 最高检 / 最高法） | 约 7000 份 | **Task 0 格式化为统一索引与文档**（index.csv + documents/*.jsonl）→ 供条目 `cases` 字段点击查看原文；禁止导入条目库，17 天版不进 AI 助手 RAG，考后/主观题阶段再评估 |
| `data/备考研究/`、`data/真题回忆版/`、`data/案例素材/` | 4 份 | 生产依据，用于 `产出依据` 与 `参考来源` 引用 |

**清洗策略：增量生产，不做一次性全量清洗。** 全量抽取约 800–1500 条，AI 生成 + 人工审核在几天内做不完，且会挤占开发时间；调度器按「增量喂入」设计，条目库每天补批次不影响已有功能。流程：

```
科目资料 → AI 抽取候选（12 字段 draft 条目，E/W 规则校验）
        → 人工只审核近 1-2 天要用的批次（draft → final）
        → 调度器只消费 final 条目
```

**首批初始化规模：300–400 条 final 条目。** 先出刑法、民法各 50 条（高频考点）共 100 条跑通全链路并验证质量，再补其余 5 科高频，合计 300–400 条（约等于每天 30 条、10 天新学量）；之后每日增量 50–100 条（易错陷阱优先）。

### 2.2 条目字段（12+1，字段顺序固定；cases 为可选字段）

| # | 字段 | 要求 |
|---|---|---|
| 1 | id | 前缀-三位序号：MF 民法 / XF 刑法 / XS 刑诉 / MS 民诉 / SJ 商经知 / LL 理论法 / SG 三国法 |
| 2 | subject | 7 科枚举 |
| 3 | submodule | 二级模块（如 分则-财产犯罪 / 总则-犯罪构成） |
| 4 | point | 考点名，≤20 字 |
| 5 | anchor | 案例/场景句，16–36 字（含标点），不以句号结尾 |
| 6 | conclusion | 结论句，≤60 字，以句号结尾，口语带关键法条 |
| 7 | priority | 单选文本枚举：高频考点 / 易错陷阱 / 新增必考 / 普通（调度权重 0/1/2/3） |
| 8 | rationale | 为何值得记，一句话 |
| 9 | sources | ≥1 条，`[{"type":"高频\|易错\|讲义\|新规\|真题\|研究","ref":"<真实文件名>","loc":"<原文摘录句>"}]`；ref 文件名与 loc 摘录文本都必须能在 data/ 树对应文件中找到（找不到出软警告 W 不阻断）；来源类型不含案例 |
| 10 | statutes | 法条定位数组（如 ["刑法269条"]）；纯理论填 [] |
| 11 | note | 易错陷阱/关联，≤80 字，可 null |
| 12 | tts_text | 非空，≤150 字：`【{科目}·{考点}】{锚点句}。{结论句}` |
| 13 | cases | 可选，0–3 条，`[{"source":"<案例库枚举>","loc":"<定位符>"}]`；loc 必须存在于 data/案例库统一/index.csv，title 由导入时按索引自动补全（存库含 title） |

## 三、功能范围

### 3.1 页面与导航（4 Tab）

| Tab | 内容 |
|---|---|
| 今日 | 距考试倒计时、今日计划（新学/复习/错题数量）、早报卡片、快捷入口（看背/听学/自测） |
| 学习 | 三段切换：看背 \| 听学 \| 自测 |
| 报告 | 两段切换：复盘 \| 覆盖树 |
| 我的 | 设置：考试日期、每日容量参数、数据导入、DeepSeek key 配置引导 |

### 3.2 功能清单

1. **动态倒排调度**：规则计算候选队列 + DeepSeek 复核调整，给出一句话理由
2. **看背**：卡片式一屏一卡，翻面看结论，三键自评（记住了/模糊/没记住）+「问 AI」
3. **听学**：每日 TTS 连播队列 + 可选 AI 串讲（每科 3–5 分钟），自动记录播放历史
4. **自测**：每日 10 题选择题（挖空题兜底），错题反馈进次日队列
5. **AI 复盘**：早报 + 晚报，LLM 失败时退回规则模板
6. **覆盖树**：实时聚合 entries + reviews，薄弱节点标红
7. **AI 助手**：检索条目与源材料片段作为上下文，流式输出，答案带出处
8. **数据导入**：`fakao-entry/1.0` JSON → SQLite，带 E/W 校验，硬错误拒绝导入；`sources.ref` 在 `data/` 树中找不到、或 `sources.loc` 摘录文本在对应文件中不存在时，出软警告 W（不阻断），防 AI 编造出处
9. **案例原文查看**：条目 `cases` 字段（来源库 + 定位符 + 标题，标题由导入自动补全）在卡片背面与听学页渲染为「案例」chips，点击经 `/api/source` 弹出原文（案例查统一索引 / 科目资料查源文件），查不到显示「原文不可用」不崩溃

### 3.3 明确不做（17 天版本）

账号与同步、主观题模块、知识点点图谱、独立大抽查页、复杂统计图表、PWA 离线、听学中交互式提问。

## 四、技术架构

```
浏览器(手机) ──> Nginx
                 ├─ /        → Next.js (3000)   前端 UI
                 └─ /api/*   → FastAPI (8000)   数据/LLM/TTS/导入
```

- **前端**：Next.js（standalone 输出，组件化：卡片、播放器、聊天、覆盖树）
- **后端**：FastAPI + SQLite；DeepSeek 服务端调用（OpenAI 兼容协议）；edge-tts 预生成 mp3 缓存
- **部署**：Ubuntu 22 两个 systemd 服务 + Nginx 反代；密钥放 `.env` 不入库不提交
- **技术栈说明**：相比纯服务端渲染多一条 Node 构建链，换取前端体验与长期迭代空间（主观题阶段、下一年）

## 五、数据模型（SQLite）

| 表 | 关键字段 | 作用 |
|---|---|---|
| entries | id, subject, submodule, point, anchor, conclusion, priority, rationale, sources, **cases**, statutes, note, tts_text, status | 条目库（12+1 字段搬入；priority 为文本枚举，cases 存库含 title） |
| cases | source, loc, title, category, case_no, keywords, date, url, text | 案例库统一文档（Task 0 JSONL → SQLite，幂等装载） |
| reviews | entry_id, ts, mode(看/听/测), result(记住了/模糊/没记住/仅暴露), duration_sec | 全量学习历史，FSRS 升级数据底座 |
| quizzes | entry_id, 题型, 题干, options(JSON), answer, source | 自测题缓存（AI 生成一次，不重复花费） |
| quiz_answers | quiz_id, ts, user_answer, correct, duration_sec | 自测作答记录 |
| daily_plans | date, items(JSON), quota, rationale | 每日队列 + 倒排依据 |
| reports | date, kind(早报/晚报), content | AI 复盘历史 |
| chat_logs | ts, question, answer, related_entry_ids, source_refs | AI 助手历史，可回溯并喂给复盘 |

覆盖树不落库，由 entries + reviews 实时聚合（量级几千条，毫秒级）。
`/api/source?ref=<来源库|文件名>&loc=<定位符|原文摘录>`：ref 为案例库枚举时查 cases 表（loc 为定位符）；否则按文件名递归查 `data/` 树，以 loc 原文摘录做子串检索，返回命中位置所在段落。

## 六、核心逻辑

### 6.1 动态倒排调度

```
输入：剩余天数 D、每日容量 C、条目状态分布（未学/复习中/错题）
1. 容量 C = 最近 3 天实际完成量移动平均（设保护上限，防贪多）
2. 候选排序：错题 > 到期复习 > 新条目（高频考点 > 易错陷阱 > 新增必考 > 普通）
3. 配比权衡：天数充足 → 复习占比高；天数紧 → 新学占比高保覆盖
4. 规则算出候选队列 → DeepSeek 复核调整，给出一句话理由
```

### 6.2 三级调度规则

| 自评 | 安排 |
|---|---|
| 记住了 | 2 天后再复习 |
| 模糊 | 明天复习 |
| 没记住 | 明天复习 + 进错题置顶队列 |

听学只记暴露次数、不计掌握；掌握判断只认看背自评与自测对错。

### 6.3 AI 复盘

- **晚报**（睡前自动生成）：今日完成度、新学/复习/错题数、自测正确率、薄弱子科目、听学时长、明日计划草案
- **早报**（打开今日面板展示）：今日计划 + 重点提醒（昨日错题、高风险考点、距考试天数）
- **实现**：规则统计先生成数据骨架 → DeepSeek 润色为报告；LLM 不可用时退回纯规则模板，复盘永远有输出

### 6.4 听学

- 每日队列 = 今日卡片 TTS 连播（按科目分段）+ 可选 AI 串讲（DeepSeek 生成文本 → edge-tts 合成，缓存复用）
- 播放器：倍速 / 前后跳过 / 单科循环；逐条记播放历史
- 不做「听学中暂停提问」：白天边工作边听，交互式提问不现实；检验交给晚上自测

### 6.5 自测

- 每日 10 题：70% 今天学过的 + 30% 昨日错题
- 选择题优先（DeepSeek 生成、缓存于 quizzes 表），挖空题规则兜底
- 对错写入 quiz_answers，直接进入错题队列与复盘数据

## 七、AI 助手（RAG-lite）

1. 提问时检索相关条目（考点/锚点/结论全文匹配）与参考来源指向的源材料片段——`sources.ref` 为文件名，按 `data/` 树递归匹配（如 `科目资料/刑法/刑法-高频考点.md`）；`sources.loc` 为该文件内的原文摘录，命中后返回所在段落上下文
2. 检索结果拼入 prompt 给 DeepSeek，要求答案带出处与法条定位
3. 流式输出（SSE），聊天历史存 chat_logs
4. 入口：全局悬浮圆钮 + 看背卡片内「就这个考点提问」快捷入口

---

## 八、UI 要点（移动优先）

- 看背：一屏一卡，点击翻面（考点 → 结论），底部三键 +「问 AI」，左右滑切卡
- 卡片背面与听学页：「案例」chips 与「来源」分开，点击弹出原文弹层（底部抽屉）
- 今日面板：倒计时 + 今日数字 + 早报卡片 + 三个快捷入口
- 听学：迷你播放器固定底部（切页不中断），显示当前科目/条目/进度，支持倍速
- 覆盖树：逐层展开，状态着色——灰=未学、蓝=已学、红=薄弱、绿=掌握
- AI 助手：悬浮圆钮，流式输出，答案附出处

## 九、错误处理与降级

| 故障 | 兜底 |
|---|---|
| DeepSeek 超时/失败 | 调度与复盘退回纯规则模板，功能不中断 |
| edge-tts 合成失败 | 前端降级浏览器语音合成，或标记「音频待补」 |
| 数据导入硬错误 | 拒绝导入并给出 E 码报告，不半写入库 |
| 音频队列未就绪 | 今日面板显示「生成中」，先看背不阻塞 |
| 案例/来源原文查不到 | 弹层显示「原文不可用」，页面不崩溃 |

## 十、测试与验收

- pytest：调度器纯函数（三级规则、倒排配比）、导入校验（含 cases 索引校验）、案例库装载、API 层
- 前端：TypeScript + ESLint + 构建通过 + 手机浏览器冒烟
- **全链路验收标准**：导入真实 JSON → 生成今日队列 → 完成一轮看背 + 听学 + 自测 → 产出早报晚报，全链路跑通

## 十一、部署（Ubuntu 22）

1. git 仓库 → 服务器 `git pull`
2. 两个 systemd 服务：uvicorn（FastAPI:8000）+ next standalone（Next.js:3000）
3. Nginx 路由：`/` → Next.js，`/api/*` → FastAPI
4. DeepSeek key 写服务器 `.env`
5. 有域名配 HTTPS，无域名先 IP 访问

## 十二、风险与后续

- **17 天时间窗口**：实现顺序先核心闭环（导入 → 今日队列 → 看背/听学 → 自测 → 复盘），再补覆盖树与 AI 助手打磨
- **FSRS 升级路径**：reviews 表已按全量历史格式记录，后续可无缝接入
- **数据量假设**：条目总量约 1000–5000 条，SQLite 完全胜任；若远超此量级需复核聚合性能
- **主观题阶段**：本工具仅覆盖客观题；主观题模块留待考后扩展
- **案例库规模**：`data/案例数据/` 约 7000 份，仅作答疑/出题参考且 17 天版暂不进 RAG；若 AI 助手需要更丰富的案例依据，考后按科目/案由建索引再启用
