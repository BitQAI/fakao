# 法条驱动客观题库与遗留修复 — Spec（2026-09-20 追加）

## 1. 背景与用户要求

1. 解决上一轮遗留问题（见 `docs/superpowers/research/2026-09-20-题库抽检报告.md` 第 7 节）。
2. **客观题库数量要按 `data/法条库` 检验，尽可能覆盖新增的法本法条**——法条补全的目的
   不只是「覆盖知识点」，而是直接成为出题原料。
3. 分批次提交。

上一轮的现实是：客观题 2421 条**全部由 entries 派生**，法条库只作为条目出题时的依据来源。
新增的 158 部法/条约（约 1 万条条文）在题库里几乎没有体现——这正是本轮要补的层。

## 2. 现状审计（2026-09-20 实测）

| 维度 | 现状 |
|---|---|
| 法条库 | 213 个文件 / 16327 条条文（含国际条约、配套司法解释） |
| 条目引用 | 条目 `statutes` 字段共 2074 条引用，其中 1793 条可解析（覆盖率约 86%），对应法条库中的若干条 |
| 题库 | 客观题 2421（全部 entry 派生，`entry_id` 非空）+ 判断题 1052（法条侧 610 / 条目侧 442） |
| 缺口 | 法条库里**大部分条文从未出现在任何题目里**；条目引用过的条文也未必有题 |

## 3. 目标

- G1：建立**法条覆盖率**度量：每部法「条文总数 / 被条目引用数 / 被题目覆盖数 / 覆盖率」，
  输出 Markdown + JSON 报告，可反复运行。
- G2：新增**法条驱动的客观题**（`origin='bank'`，`entry_id IS NULL`）：
  优先覆盖「条目引用过但尚无题目」的条文，其次按每法配额补足新增法条/司法解释/国际条约。
- G3：法条题能在 App 里被用到（组卷能抽到，不只躺在库里）。
- G4：消化上一轮遗留问题：判断题对错失衡、条约类回源核验偏差、5 条条目无题、
  主观题采分点因法条库缺法规被丢弃。

## 4. 非目标

- 不为 16327 条条文逐条出题（成本不可控）。配额目标是「每部法都有题、高频法重点覆盖」。
- 不改 `quizzes` 表结构（法条题复用 `entry_id` 可空 + `basis` + `subject`）。
- 不做法条题的人工全量校对（提供抽检报告与复核入口）。

## 5. 方案

### 5.1 覆盖率度量（`app/statute_coverage.py` + `scripts/audit_quiz_coverage.py`）

- 法条库解析复用 `app/statute_index.load_library()`（已有：法名、条号、正文、章节）。
- `statutes.resolve_statute()` 增补 `resolve_law_article()`：返回 `(law_key, no, sub)`，
  供解析条目 `statutes` 与题目 `basis` 两种写法（「刑诉法91条」/「中华人民共和国专利法第九条」）。
- 每部法统计四项指标 + 覆盖率；按「被题目覆盖的条文条数 / 条文总数」排序，输出缺口最大的 30 部。
- 报告落 `docs/superpowers/research/2026-09-20-法条覆盖与题库核验报告.md`。

### 5.2 法条驱动客观题（`scripts/build_statute_quiz.py`）

候选排序：

1. **条目引用过且未被任何题覆盖**的条文（按被引用条目数降序）——最贴考点；
2. 未被覆盖的法条按每法配额补足（`--per-law`，默认 3），优先「数字型/要件型」条文
   （含期限、金额、人数、比例、应当/不得），与判断题同一套 `number_terms` 打分。

产物：`origin='bank'`、`qtype='choice'`、`entry_id=NULL`、`subject=<法名映射科目>`、
`basis='<法名><条号>'`（规范写法，便于覆盖率统计与法条页跳转）。

校验（复用 `build_quiz_bank.check_quiz` 的思路，依据换成**条文原文**）：
选项 ≥4 且不重复、答案字母合法、解析 ≥10 字、题干 ≥8 字、正确项与条文原文相关。

### 5.3 让法条题可用（`quiz_service.custom_quiz`）

组卷先取所选范围的条目题，不足题量时用 `quiz_bank.pick(origin='bank', subjects=...)`
补齐（会包含法条题）。行为是纯增量：原本能出满题量时不改变结果。

### 5.4 遗留修复

| 遗留 | 方案 |
|---|---|
| 判断题答案偏「对」（766:286） | `build_judge_bank.py` 增 `--polarity false` 与 `--include-covered`：对已覆盖法条再出一轮「错」题，把比例拉到约 55:45 |
| 条约类 12 条回源核验偏差 | 核验改两级回源：先按条号取条文，取不到则在全法文本中核验，并标注 `verify=loose`（报告里单列） |
| 5 条条目无客观题 | 重试 + 放宽判据为「正确项与（结论 ∪ 场景）相关」，仍不通过则列入待人工处理清单 |
| 主观题采分点因缺法规被丢弃 | 用 `scripts/fetch_statutes.py` 补《农村土地承包法》《种子法》等缺失法规；补不到的在报告里登记 |

## 6. 验证标准

1. `audit_quiz_coverage.py` 可运行并给出覆盖率；法条驱动出题后，**覆盖率显著上升**（记录前后数字）。
2. 法条题结构问题 0；正确项与条文原文相关（脚本核验）。
3. 判断题对/错比例落在 60:40 ~ 45:55。
4. 判断题回源核验：`strict` 不通过为 0，`loose` 命中数单列说明。
5. 组卷能抽到法条题（API 层验证：题目里出现 `entry_id=null` 的题）。
6. `pytest` 全绿；前端 `tsc`/`eslint` 无告警；如涉及页面改动需 Playwright 验证。

## 7. 风险

| 风险 | 对策 |
|---|---|
| 法条题量大导致 LLM 费用/耗时上升 | 默认每法 3 条 + 仅补未覆盖条文，支持 `--limit` 断点续跑 |
| 法条题脱离考点（照抄条文） | 出题 prompt 要求案例化；正确项必须与条文原文相关，且必须有干扰项来自易混情形 |
| 组卷行为被改坏 | 只做「不足时补齐」的增量逻辑，并加测试 |
