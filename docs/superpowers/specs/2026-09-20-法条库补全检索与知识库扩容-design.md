# 法条库补全、法条检索与知识库扩容 — Spec（2026-09-20）

## 1. 问题背景

2026 客观题已考完（9/12–13），用户备考目标调整为 **2027 客观题 + 后续主观题**，提出四项需求：

1. 新增「每日案例」模块，形态选 **B（微主观题）**，并保留 **A 变体（只听不讲）兜底**，但听完必须勾采分点。
2. 把缺失的板块补齐（考纲完整性）。
3. 补法条库缺失原文、民法 + 刑法扩容、补司法解释层。
4. 新增法条检索模块，并做合适的渲染。

### 1.1 覆盖审计结论（2026-09-20 实测）

| 层面 | 结论 |
|---|---|
| 法条原文 | `data/法条库/` 55 个文件，对照《法考现状》考查表**缺 21 部**（经济法 5 部、劳动 4 部、知产 3 部全缺）；另需补 4 部新增大纲法与 1 部司法解释，共 26 项 |
| 司法解释层 | 民法典配套解释仅 18 条条目、刑诉解释 12 条、民诉解释 9 条、两高刑事配套 0 条 |
| 条目 × 分值 | 三国法 22.0 条/分 vs 民法 3.7 条/分，**差 6 倍**；民法、刑法是最低的两科 |
| 使用行为 | `reviews` 2989 条中 `listen/exposed` 2956 条（占 98.9%），`read` 自评仅 33 次；听学覆盖 2425/2426 条，看背只碰过 13 条 |
| 闲置资产 | 案例库 7172 条（人民法院案例库 5537 条，其中 1752 条含明确「争议焦点」段），与条目挂接率仅 19% |

**核心判断**：问题不是「知识库不够厚」，而是「知识库与应试能力之间缺层，且条目数量与分值权重反向」。法条库缺原文还导致流水线中「法条可解析」校验对相当一批条目**静默失效**。

---

## 2. 目标与非目标

### 2.1 目标

- G1：法条库对考查表**零缺口**，且每部法有可复现的抓取来源记录。
- G2：法条可**主动检索与阅读**（不再只能从卡片点开单条），条文渲染可读。
- G3：新增「每日案例」训练闭环（写要点 → 采分点核对 → 未命中回写复习）。
- G4：条目总量从 2426 提升到约 3260，优先级为**民法 → 刑法 → 司法解释层 → 空白板块**；三国法不再增量。
- G5：为无法条可依的科目（理论法、三国法理论部分）建立**外部资料引入路径**（见 6.4）。

### 2.2 非目标（本轮明确不做）

- 不做主观题整卷 4 小时模考（形态 C，留到 2027 年 9 月客观题结束后）。
- 不引入 FSRS／间隔重复算法（当前历史数据不足，改用「优先级 × 剩余天数」倒排）。
- 不做条文新旧版本 diff 对照工具（本轮只收录现行有效版，版本信息写进文件头）。
- 不做 web 端以外的平台适配。

## 4. Phase 1：法条库补全 + 法条检索模块

### 4.1 法条抓取

**来源**：国家法律法规数据库 flk.npc.gov.cn（与现有 55 个文件同源，文件头已记录 `bbbs`）。

**已实测可用的接口**（2026-09-20 验证）：

- `POST /law-search/search/list`，JSON body `{searchRange, searchType, searchContent, page, size, ...}`，返回 `{total, rows:[{bbbs, title, gbrq, sxrq, sxx, flxz, zdjgName}]}`。
- `GET /law-search/search/flfgDetails?bbbs=...`，返回元信息 + `ossFile{ossWordPath, ossPdfPath, ...}`；**全文不在该响应里，需下载 docx/pdf 再转换**。
- 注意：旧站 `bbbs` 在新接口下不解，必须按标题重新检索取新 ID。

**新增脚本** `backend/scripts/fetch_statutes.py`：

1. 按法名标题检索 → 取候选版本列表；
2. **版本选取规则**：取 `sxrq`（施行日期）≤ 目标备考年度且最新的有效版本；若存在「已公布未施行」的版本（如《商标法》2026-06-26 公布、2027-01-01 施行），**两个都记入文件头**，正文收最新版并标注生效日；
3. 下载 docx → 转文本 → 归一为现有格式：`# 法名` + 元信息头（公布/施行/效力状态/制定机关/来源 bbbs）+ 目录 + `第X条　正文`；
4. 幂等：目标文件已存在且 bbbs 一致则跳过，支持 `--only 法名` 断点续跑。

**补齐清单**（26 项）：

| 板块 | 缺失项 |
|---|---|
| 经济法（5） | 反垄断法、反不正当竞争法、消费者权益保护法、产品质量法、食品安全法 |
| 劳动与社会保障（4） | 劳动法、劳动合同法、社会保险法、劳动争议调解仲裁法 |
| 知识产权（3） | 著作权法、专利法、商标法 |
| 环境资源（2） | 土地管理法、城市房地产管理法 |
| 理论法（2） | 法官法、律师法 |
| 三国法（1） | 涉外民事关系法律适用法 |
| 商法（3） | 个人独资企业法、外商投资法、海商法 |
| 行政法（1） | 公务员法 |
| 司法解释（1） | 民法典婚姻家庭编的解释（二）〔法释〔2025〕1 号〕 |
| 新增大纲法（4） | 治安管理处罚法（2025 修订）、生态环境法典、民族团结进步促进法、国家发展规划法 |

**待核实项**：生态环境法典、民族团结进步促进法、国家发展规划法是否已正式颁布并生效。若尚未颁布，**不收录正文**，改为在 `data/科目资料/理论法/` 记录考点说明，并在本 Spec 的验收项中标记为「待颁布后补」。

**第二批（2026-09-20 审计修正）**：跑 `backend/scripts/audit_statute_citations.py` 后发现上面 26 项**不足以覆盖真实缺口**。审计基线为 693 条不可校验引用 / 144 种法名，补别名后降到 655 条 / 133 种，剩余按性质分三类：

| 类别 | 规模 | 典型条目 | 说明 |
|---|---|---|---|
| 法律本体缺文件 | 72 种 / 440 条 | 劳动合同法 71、专利法 43、商标法 39、涉外民事关系法律适用法 35、著作权法 32、反垄断法 28 | 与上面的 26 项清单基本重合，是主要缺口 |
| **国际条约** | **31 种 / 162 条** | CISG 33、Incoterms 2020 20、联合国海洋法公约 16、维也纳外交关系公约 11、维也纳条约法公约 11、TRIPS 11、联合国宪章 8、伯尔尼公约 8 | **原清单完全遗漏**。三国法（17 分）的法条主体就是条约，必须补 |
| 配套法规与司法解释 | 30 种 / 53 条 | 工伤保险条例 7、醉驾意见 5、政府信息公开条例 4、认罪认罚指导意见 3、职工带薪年休假条例 3、反外国不当域外管辖条例 2 | 集中在劳动、环资、行政、刑诉配套 |

另有若干以**文号**而非名称引用的（法释〔2024〕13 号、法释〔2025〕9 号批复、国务院令第 784 号等），需要单独建立「文号 → 文件」映射，不能靠法名别名解决。

### 4.2 数据模型

**不新增数据库表**。法条库保持「文件 + 运行时解析」形态，与现状一致：

- `data/法条库/*.md`：唯一数据源。
- `app/statutes.py`：保持不变，只负责「简称 → 文件 → 单条正文」（现有能力）。
- **新增** `app/statute_index.py`：负责全量索引与检索，与 `statutes.py` 分开以避免文件超限。
  - 启动/首次访问时构建内存索引：`{法名: {章节目录, {条号: 正文}}}` + 正排（条文全文倒排）。
  - 现有 55 个文件 + 新增 26 项，冷启动一次解析后常驻缓存；与现有 `_LAW_FILE_CACHE` 解耦，避免影响原有惰性加载路径。

## 5. Phase 2：每日案例模块（形态 B + A 兜底）

### 5.1 形态定义

**B（主形态，微主观题）**

1. 题干：案情压缩至 ≤400 字；
2. 设问：2–3 问；
3. 作答：限时 10 分钟（软约束，超时提示但允许继续），文本框写要点；
4. 提交后展示**采分点核对表**：逐条勾选「我写到了」；
5. 未命中的采分点 → 自动写入错题/复习池，并链接对应考点条目与法条原文；
6. 得分 = 命中采分点数 / 总采分点数。

**A 变体（听讲兜底）**

1. 通勤/状态差时选「只听」：TTS 播题干 + 设问，**不播答案**；
2. 播放结束后**必须完成采分点勾选**才能记为完成，否则本条不计入当日进度（防止退化成纯听）；
3. 复用现有 TTS 流水线（`app/tts.py`）。

**设计要点**：LLM 只负责「压缩案情 + 抽采分点」，**不负责评判用户文字**——采分点在裁判理由里有原文依据，可回溯、可人工核对，规避主观题自动打分的可靠性问题。

### 5.2 数据模型（新增两张表）

```sql
CREATE TABLE case_questions (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  case_source   TEXT NOT NULL,      -- 案例库来源，如 人民法院案例库
  case_loc      TEXT NOT NULL,      -- 定位符，如 case_00001
  subject       TEXT NOT NULL,      -- 刑法/民法/刑诉/民诉/商经知劳环/行政法
  stem          TEXT NOT NULL,      -- 压缩后案情（≤400 字）
  questions     TEXT NOT NULL,      -- JSON: ["设问1","设问2"]
  points        TEXT NOT NULL,      -- JSON: [{no, text, statutes:[...]}]
  reference     TEXT NOT NULL,      -- 参考答案（裁判理由摘要）
  status        TEXT NOT NULL DEFAULT 'draft',  -- draft | published
  created_at    TEXT NOT NULL
);

CREATE TABLE case_attempts (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  question_id  INTEGER NOT NULL REFERENCES case_questions(id),
  ts           TEXT NOT NULL,
  mode         TEXT NOT NULL,       -- write | listen
  answer_text  TEXT,                -- 手写要点；listen 模式为空
  hit_points   TEXT,                -- JSON: 命中的采分点编号数组
  score        INTEGER,             -- 0-100
  duration_sec INTEGER NOT NULL DEFAULT 0
);
```

**建表方式**：本项目无 Alembic（SQLite + `app/db.py` 的 `SCHEMA_SQL` + `CREATE TABLE IF NOT EXISTS` 幂等初始化）。新表**追加到 `SCHEMA_SQL`**，不引入迁移框架——那属于本轮范围外的基建变更。`tests/test_db.py` 增加新表存在的断言。

`daily_plans.items` 扩展（**向后兼容**）：新增元素形态 `{"kind":"case","question_id":N,"bucket":"new"}`；旧元素无 `kind` 字段，按 `entry` 处理。

### 5.3 生成流水线

**新增脚本** `backend/scripts/build_case_questions.py`：

1. **筛选候选**（可从 1752 条含「争议焦点」的案例中筛）：
   - `source = '人民法院案例库'`；
   - 正文含「争议焦点」；
   - 能归类到考纲科目（复用 `app/case_terms.py` 的领域门槛逻辑）；
   - 正文长度在合理区间，避免超长判决书。
2. **按科目配额**分批（刑法 / 民法 / 刑诉 / 民诉 / 商经知劳环 / 行政法），每日仅需 1 题，但先备足一个月的量。
3. **LLM 加工**（每次 1 条案例）：输出 `{stem, questions, points[], reference}`；`points` 每点必须带 `statutes` 依据，且依据条号必须在法条库中可解析（**依赖 P1**）。
4. 落库 `status='draft'` → 抽样人工核对 → 批量置 `published`。
5. 幂等：按 `(case_source, case_loc)` 唯一，重复运行只补不覆盖。

### 5.4 API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/cases/daily` | 今日案例题（返回题干/设问，**不含答案与采分点**） |
| POST | `/api/cases/{id}/answer` | 提交手写要点，返回采分点核对表（此时才下发采分点文本） |
| POST | `/api/cases/{id}/grade` | 提交勾选结果，返回得分、未命中采分点、关联条目与法条 |
| GET | `/api/cases/history?limit=` | 历史记录与正确率统计 |
| GET | `/api/cases/{id}` | 单题详情（含参考答案，用于复习） |

### 5.5 前端

- 学习页 `study/page.tsx` segments 增加「案例」（第 5 项，segments 改为可横向滚动）。
- 新增 `frontend/src/components/CaseView.tsx`（题面 + 计时 + 作答 + 采分点核对），超过 300 行则按「题面」「核对表」拆子组件。
- 今日页展示「今日案例」入口卡片。

### 5.6 验证标准

- 新增 `tests/test_case_questions.py`：题干长度上限、采分点法条可解析、唯一键幂等。
- 新增 `tests/test_case_module_api.py`：daily 不泄露答案、answer 后才返回采分点、grade 计分正确。
- 前端 Playwright 自验全流程：选题 → 作答 → 提交 → 勾采分点 → 得分 → 未命中点回写复习池。

## 6. Phase 3 / 4：知识库扩容流水线（方案 a：法条原文 + 案例反推）

### 6.1 上游构造

**新增脚本** `backend/scripts/build_upstream_from_statutes.py`：

- 输入：`data/法条库/<法>.md` 的编/章/节结构 + `cases` 表中该领域的案例（`争议焦点` / 裁判理由 段）+ 可选的外部资料块（见 6.4）；
- 输出：`data/科目资料/<科目>/<法>-法条与案例.md`，块结构沿用现有 `## / ###` 约定，块内容 = 条文摘录 + 相关案例的争议焦点与裁判理由摘要；
- 目标：让每个资料块都同时具备「法条依据」与「情境素材」，从源头抑制「法条复述型」条目的产生。

**适用性限制（重要）**：本流水线**仅适用于有法条可依的科目**（民法、刑法、刑诉、民诉、商经知劳环、行政法）。理论法（法治思想、法理学、中国法律史、司法制度和法律职业道德）与三国法的国际法／国际经济法理论部分**没有条文骨架**，本流水线不成立，必须走 6.5 的外部资料路径。

### 6.2 生成与校验

- 生成：复用 `backend/scripts/generate_entries.py --subject X --gaps --batch 2`（表格块必须 `--batch 2`）。
- **importer 校验扩展**：`sources` 需支持 `{type:"案例", ref:"人民法院案例库", loc:"case_00001"}`，校验规则为「法条 loc 在法条库可解析 + 案例 loc 在 `cases` 表存在」。
- 质量红线（新增校验）：`anchor` 必须是情境句、`conclusion` 必须是判断结论；出现「本法规定」「依照法律规定」等复述型表述的条目降级为 WARN 并人工复核。
- 导入 → `UPDATE entries SET status='final' WHERE status='draft'` → `synthesize_audio.py` → `match_cases.py --append-guiding`。

### 6.3 分批计划与规模目标

| 批次 | 科目 | 现状 | 目标 | 重点 |
|---|---|---|---|---|
| P3-a | 民法 | 180 | 400 | 民法典配套司法解释（合同编通则、担保制度、侵权责任编）、人格权/婚姻家庭/继承编 |
| P3-b | 刑法 | 162 | 350 | 分则罪名（财产、人身、破坏市场经济秩序）、两高解释 |
| P3-c | 刑诉 / 民诉 | 260 / 228 | 340 / 300 | 刑诉解释 655 条、民诉解释 549 条、两高刑事配套 |
| P4-a | 商经知劳环 | 675 | 850 | 经济法 5 部、劳动 4 部、知产 3 部、环资 2 部（当前 0–12 条） |
| P4-b | 理论法 / 行政法 / 三国法 | 371 / 176 / 374 | 420 / 220 / 380 | 法官法、律师法、公务员法、新增大纲法；三国法只补涉外法律适用法。**理论法依赖外部资料，见 6.4** |

合计目标约 3260 条（现 2426）。

**关于条/分比**：本轮**不追求把各科比值强行对齐**。目标是消灭最低配的两科——民法 3.7、刑法 4.3 提到 8 以上；对已超配的科目（三国法 22.0、商经知劳环 11.6）只做结构性补充，不再增量。理由是三国法条目偏碎、元信息块多，实际考点密度低于条目数所反映的水平。

预计 LLM 调用约 250–400 次（每次 2–5 块）。**开工前必须先探活 DeepSeek API**（当前有欠费历史）。

### 6.4 外部讲义／教材／机构资料的引入路径

**为什么需要**：方案 a 的法条 + 案例路径对理论法与三国法理论部分失效（无法条骨架）。这几科要扩容，外部资料是唯一来源，不是可选项。

**目录与格式**

- 新增 `data/外部资料/<科目>/<来源>-<主题>.md`，块结构沿用 `## / ###`，与 `data/科目资料/` 同构，便于同一套 `generate_entries.py` 复用。
- **原始文件（PDF／EPUB／扫描件）加入 `.gitignore`，转换后的 `.md` 正常入库**。理由与既有先例一致：`data/案例数据/`（约 69MB）与 `data/案例库统一/documents/` 就是按体积不入库，而体积小、需版本追踪的文本一律跟踪。转换后的 md 是条目生成的上游，必须能进 git 追溯。
- 转换链路：PDF／EPUB／扫描件 → 文本（`pdftotext`／`markdownify`／必要时 OCR）→ 人工或脚本切块 → 落目录。转换质量差（乱码、断行错乱）的资料直接废弃，不将就入库。

**三条使用边界**（防止二手转述污染题库）

1. **只用于「考点发现与组织」**——确定某条法条下该讲哪些点、怎么排序、有哪些对比表与口诀，不直接当作条目的依据来源。
2. **有法条可依的科目，sources 必须至少含一条权威依据**（法条原文或案例）；外部资料可同时登记为追溯来源，但不得是唯一来源。无法条科目（理论法等）允许以外部资料为来源，但条目需标注依据类型为「理论」，且整理时人工核对与大纲／马工程教材口径一致。
3. **冲突时以法条和司法解释为准**。本仓库已踩过同类坑：2026 真题回忆稿里「行政复议前置只有三类」是旧法口径，与库内依据新《行政复议法》的条目直接冲突（见 `data/真题回忆/2026-客观题-回忆整理.md` 第 6.3 节）。机构资料属二手转述，出现冲突一律不改库内权威条目。

**适用优先顺序**

| 科目 | 是否依赖外部资料 | 说明 |
|---|---|---|
| 理论法（法治思想／法理学／法制史／司法制度） | **必须** | 无法条骨架，方案 a 不适用 |
| 三国法（国际法／国际经济法理论部分） | **必须** | 同上；涉外民事关系法律适用法有条文，走法条路径 |
| 民法／刑法／刑诉／民诉／商经知劳环／行政法 | 可选补充 | 用于记忆框架、对比表、易混点组织 |

### 6.5 验证标准

- 每批生成后 `import_entries.py` 的 `errors=0`。
- `generate_entries.py --subject X --gaps --dry-run` 缺口块归零。
- 民法、刑法条/分比提升到 8 以上；三国法条目总数不增加。
- 全部导出的新条目 `statutes` 引用可解析率 100%。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 官方站 API 再次变更 | 抓取中断 | 抓取脚本可断点续跑；文件名与 bbbs 记录在文件头，便于核对 |
| 新法版本与生效日混淆（如商标法 2027-01-01 施行） | 收录了错误版本 | 版本选取规则写死在脚本；文件头同时记录公布日与施行日 |
| LLM 生成「法条复述型」条目 | 条目质量下降 | 上游改造为「法条 + 案例情境」双源；新增 anchor/conclusion 形态校验 |
| DeepSeek 欠费 | 扩容停滞 | 每批开工前探活，欠费即暂停并告知 |
| 案例题采分点质量不稳 | 训练误导 | 采分点必须带可解析法条依据；先 `draft` 抽样人工核对再 `published` |
| 外部资料与法条口径冲突 | 题库被二手转述污染 | 冲突时以法条／司法解释为准；外部资料不得作为有法条科目的唯一依据（见 6.4 三条边界） |
| 外部资料转换质量差（扫描件乱码、断行错乱） | 生成垃圾条目 | 转换质量不达标直接废弃；原始文件只留本地，转换后的 md 入库便于追溯 |
| 条目扩容后队列爆炸 | 每日计划不可用 | 与 G4 同期调整调度：改为「优先级 × 剩余天数」倒排，容量上限沿用现有 `capacity_max` |
