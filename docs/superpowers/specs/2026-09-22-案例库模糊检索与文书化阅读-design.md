# 案例库模糊检索与文书化阅读 — Spec（2026-09-22）

## 1. 问题与用户要求

1. 法条已经能「搜得到、读得顺」（`/statutes`：法名清单 + 全文检索 + 分章阅读）。
2. 案例库现状**只有反向打开**：条目挂接的 `cases` 能通过 `SourceViewer` 弹出原文，
   但没有入口可以主动搜案例，也读不出一篇「像判决书」的样子。
3. 要求：① 模糊检索已有案例（现有 7172 条，4 个来源库）；② 把原文按正式文书结构排版，
   方便阅读（裁判要旨 / 基本案情 / 裁判理由 / 裁判结果 等分节）。

## 2. 现状审计（2026-09-22 实测）

| 项 | 现状 |
|---|---|
| 数据 | `data/案例库统一/index.csv`（元数据）+ `documents/<来源库>.jsonl`（全文），已装载进 `cases` 表 7172 行 |
| 表结构 | `cases(source, loc, title, category, case_no, keywords, date, url, text)`，主键 `(source, loc)`；**无需改动** |
| 后端 | `app/cases.py` 只有 `ensure_cases_loaded` / `get_case`；`GET /api/source?ref=&loc=` 可打开单篇 |
| 前端 | `SourceViewer` 只是一段纯文本弹层；无案例检索页、无案例导航入口 |
| 原文形态 | 4 个来源的分节标记不同（见 §4.1）：人民法院案例库为「编号要旨段 + 正文段」，最高检/司法部用 `【小节】`，最高法用裸行小标题 |
| 脏数据 | 个别案例正文存在**连续重复段落**（实测 `case_01020` 有整段重复），直接渲染会重复阅读 |

## 3. 方案概要

与法条页同构，新增一条平行的「案例库」读路径，只读、不改表、不新增表：

```
前端 /cases                                  后端
  KeywordSearch（关键词）                       GET /api/case/search?q=&source=&limit=
  CaseLibraryList（命中列表，带片段高亮）   <--   app/case_index.search()
  CaseDocument（文书化阅读）                <--   GET /api/case/detail?source=&loc=
                                                   app/case_index.sections()
  BottomNav 第 5 个 tab「案例」                  GET /api/case/stats（4 库条数）
```

路径用单数 `/api/case/*` 与已有的 `/api/cases/{qid}`（主观题，`qid: int`）区分：
`/api/cases/search` 会被 `{qid}` 路由按字符串先匹配掉并返回 422（已实测），必须避开。

## 4. 详细设计

### 4.1 文书分节规则（`app/case_index.sections()`）

三种解析策略，按优先级尝试，返回 `[{label, text}]`（`label` 为空表示无标题正文段）：

| 来源 | 原文标记 | 解析方式 |
|---|---|---|
| 最高检指导性案例 | `【关键词】【要旨】【基本案情】【检察机关履职过程】【指导意义】【相关规定】` | 按 `【X】` 切段 |
| 司法部案例库 | `【案情简介】【调解过程】【调解结果】【案例点评】` 等 | 按 `【X】` 切段 |
| 最高法指导性案例 | `关键词`/`裁判要点`/`相关法条`/`基本案情`/`裁判理由`/`裁判结果` 独占一行 | 按已知小标题行切段 |
| 人民法院案例库 | 正文段首为 `1.` `2.` 编号的**裁判要旨**，其后为案情与裁判理由（无标记） | 前置编号段归为「裁判要旨」，其余为无标题正文 |

统一后处理：

- 清理原文页眉页脚：markdown 标题记号、`（发布批次：…）`、`指导性案例第N号：…`、
  分隔线 `---`、以及最高检正文末尾残留的下一篇案例标题；
- 行尾无句末标点时与下一行拼接（关联法条行、`一审/二审：` 行视为完整行，不参与拼接）；
- 人民法院案例库（无标记来源）额外把正文末尾的**关联法条行**与**一审/二审行**抽成
  `相关法条`、`审理程序` 两个小节（实测 800 条样本中 660 条含程序行、569 条含法条行）；
- 删除连续重复的句子/句块（实测 30 个案例存在整句被判词复制两遍的脏数据），
  响应里给出 `paragraphs_dropped`；
- 小节顺序：`关键词` → `裁判要旨/要旨/裁判要点` → `相关法条/相关规定` → 正文其余 → `审理程序`；
- 每条 section 文本 strip 后为空则丢弃。

### 4.2 模糊检索（`app/case_index.search()`）

- 输入 `q`：按空白/顿号/逗号拆成多个词，词之间是 AND（全部命中才算）；
- 命中字段权重：`title` 6 > `case_no` 4 > `keywords` 3 > `category` 2 > `text` 1；
  全部关键词都在标题里额外加权；
- 排序：权重降序 → 有 `case_no` 优先 → `date` 降序 → `source, loc`；
- 返回 `source/loc/title/category/case_no/keywords/date/url/snippet/score`，
  `snippet` 取首个命中位置前后各 40 字（仅标题命中时取正文开头）；
- `source` 可选过滤；`limit` 默认 30、上限 100；
- 纯 `LIKE` 实现，7172 行规模下无需新索引或外部依赖（本地实测扫描成本可忽略）。

### 4.3 API

| 方法 | 路径 | 参数 | 返回 |
|---|---|---|---|
| GET | `/api/case/search` | `q`(必填,≤50)、`source`(可选)、`limit`(默认30,≤100) | `{items, total, query}` |
| GET | `/api/case/detail` | `source`(必填)、`loc`(必填) | 元数据 + `keywords[]` + `sections[]` + `paragraphs_dropped` |
| GET | `/api/case/stats` | 无 | `{total, sources: [{source, n}]}` |

- 案例未装载（新库）时沿用 `cases.get_case` 的懒装载行为；
- `source` 不在 4 库枚举 → 404（不报 500）；
- 空 `q` → 返回空列表（不报错），与 `/api/statute/search` 一致。

### 4.4 前端

| 文件 | 角色 |
|---|---|
| `frontend/src/app/cases/page.tsx` | 页面：搜索框 + 来源筛选 + 结果列表 / 阅读视图（URL 参数 `q`、`source`、`loc`、`lib`） |
| `frontend/src/components/CaseLibraryList.tsx` | 命中列表：标题、来源·类别·案号·日期、片段（命中词高亮） |
| `frontend/src/components/CaseDocument.tsx` | 文书化阅读：标题区 + 分节正文 |
| `frontend/src/lib/caseLibTypes.ts` | 前端类型定义 |
| `frontend/src/components/BottomNav.tsx` | 新增第 5 个 tab「案例」（图标复用 `IconLaw`，不新增图标资产） |

阅读视图按正式文书排版：标题居中加粗、案号与来源信息行、关键词标签、分节小标题带左侧色条、
正文段首缩进两字、行距 1.8。

### 4.5 与已有入口的关系

- 条目里挂接的 `cases` 仍走 `SourceViewer`，本期不改：它是弹层「看一眼原文」，改造属额外范围，
  避免影响看背/听学的既有路径。
- 案例页的「相关法条 / 相关条目」本期不做，留待后续独立需求。

## 5. 验证标准

1. `backend/tests/test_case_index.py`：4 个来源的分节结果、连续重复段删除、多词 AND 检索、
   标题命中排前、`source` 过滤、空 `q` 返回空、`limit` 生效。
2. `backend/tests/test_api_case_library.py`：三个接口的状态码与载荷结构；
   `/api/cases/{qid}`（主观题）行为不变（回归）。
3. `pytest tests` 全绿（基线 170+）。
4. Playwright 在 `localhost:3001` 实机走一遍：搜「房屋租赁」→ 出结果 → 点开 → 看到分节标题与正文 →
   console 无错误；截图存 `frontend/e2e/shots/`。

## 6. 范围边界

- 不改 `cases` 表结构、不加索引、不引入新依赖、不动构建配置。
- 不做案例收藏/标注/朗读（属后续独立需求）。
- 不做全文语义检索（LLM/向量），本期只做确定性的关键词模糊检索。
- 分节解析属展示层能力，不写回数据库，原文永远保留在 `cases.text`。
