# Spec：听背已听次数显示与自定义优先排序优化

- 日期：2026-09-01
- 状态：待评审
- 涉及模块：
  - frontend: ListenView, types.ts, progressStore（复用）
  - backend: service.py, review_stats.py, routers/plans.py, entry_by_id
  - data: reviews 表（mode=listen 聚合，不改表结构）

## 1. 问题背景

用户反馈两点：

1. **听背未像看背那样显示已听次数**：看背 `FlashcardView` 进度行持续显示 `本条已看 N次`、`今日累计 N条`、`本次完成 N张` 及卡片角标 `今日已看`；听背 `ListenView` 仅在标题显示 `已听 N次` 徽标（0 时隐藏），页脚仅 `累计已听 heardTotal · 剩余可听`，缺乏 `本条已听` 的进度行、`今日累计` 与 `今日已听` 徽标，刷新后也无当日维度记忆。
2. **自定义听背范围未优先播未听部分**：默认听学池 `_listen_pool` 已按 `未听优先 → 听次少优先 → 久未听优先 → 优先级 → 科目` 排序；但 `custom_entries(listen_only=True)` 自定义范围仅按 `listen_count → priority → subject → id`，缺 `last_ts` 一档，同次数下按优先级而非“越久未听越前”，与默认池割裂；且 `attach_reviewed_today` 仅查 `mode=read`，听学无 `listened_today` 字段，前端无法展示 `今日已听`。

既有 2026-09-01 优化已将自定义范围排序改为 `read/listen_count` 优先，但听学仍未对齐 `_listen_pool` 的完整二段排序与当日标记。

## 2. 方案概要

### 2.1 显示对齐（前端 ListenView 对标 FlashcardView）

- 进度行新增：
  - `第 idx+1 段 / 队列 len · 本条已听 N次（0 显示“未听”）· 今日累计 M条（当日去重）· 累计已听 heardTotal`
  - 保留原有 `剩余可听` ，语义与看背 `本次完成/今日累计/本条已看` 对称
- 卡片标题徽标：
  - 保留 `已听 N次`（N>0），新增 `今日已听` 徽标（当 `entry.listened_today || listenedToday.has(id)`）
- 本地态即时更新：`markExposed()` 成功（≥10s 且首次暴露）后本地 `entry.listen_count++`、`listenedToday.add(id)`、`heardTotal` 增量，无需等待刷新
- 自定义范围加载与续听时，并行拉取 `GET /api/reviews/history?mode=listen&limit=500` 提取当日 `entry_id` 合并入 `listenedToday`（与看背 `mode=read` 逻辑对称）

### 2.2 排序统一（后端 service 抽公共函数）

- 抽 `def _sort_listen_items(items: list[dict]) -> list[dict]` 供 `_listen_pool` 与 `custom_entries(listen_only=True)` 复用
- 规则：
  1. 分组：`never = listen_count==0`，`heard = listen_count>0`
  2. `never` 组内：`priority_order ↑, subject_order ↑, id ↑`（与现 `_listen_pool.never` 一致）
  3. `heard` 组内：`listen_count ↑, last_ts ↑（空串视为最早，即最久未听）, priority_order ↑, subject_order ↑, id ↑`
  4. 返回 `never_sorted + heard_sorted`
- 效果：未听永远在前；同次数下越久未听越前；仍尊重优先级与科目顺序作为同层 tie-breaker
- `custom_entries` 中：先 `attach_listen_counts` 拿到 `listen_count/last_ts`，再调用 `_sort_listen_items`，最后按 `limit` 切片；`remaining` 语义保持 `len(filtered)-len(slice)`（与现有一致）

### 2.3 当日标记（后端 review_stats）

- 新增 `attach_listened_today(conn, items, day=None)`：`SELECT DISTINCT entry_id FROM reviews WHERE mode='listen' AND date(ts)=? AND entry_id IN (...)`，写入 `it.listened_today: bool`
- `service.custom_entries(listen_only=True)`、`service._listen_pool`、`service.entry_by_id`、`service.listen_queue` 返回的每条均附加 `listened_today`（与 `attach_reviewed_today` 对称）
- 为兼容旧前端，保留 `reviewed_today` 字段不变；新增字段不影响旧客户端

## 3. 技术选型

- 不新增表/列，复用 `reviews` 聚合（COUNT + MAX + DISTINCT date）
- 排序在 Python 层完成（候选集 ≤200/100，O(n log n) 可接受），避免 SQL 复杂窗口
- 前端 `listenedToday` 用 `Set<string>` 内存态，刷新后通过 `history?mode=listen` 重建，与看背 `reviewedToday` 完全对称
- 不引入 SRS 间隔、权重衰减等复杂算法，保持“未听 > 少听 > 久未听”可解释性

## 4. 数据模型

- 无 DDL
- Entry 运行时字段新增 `listened_today?: boolean`（前端 `types.ts`）
- 后端每条返回附加 `listen_count: int, last_ts: string|null, listened_today: bool`

## 5. API 设计

### `POST /api/listen/custom`
- 请求不变：`{subjects, points, limit(1-500截断100), exclude}`
- 响应：`{items: Entry[], remaining: number, heard_total: number, generating: false, custom: true}`
- 变更：`items[*]` 新增 `listened_today`，且按 `_sort_listen_items` 排序

### `GET /api/listen`（默认池）
- 响应不变，`items[*]` 新增 `listened_today`（已通过 `_listen_pool` 附加）

### `GET /api/entries/{id}`
- 返回单条新增 `listened_today`

### `GET /api/reviews/history?mode=listen&limit=500`
- 已存在，前端用于构建 `listenedToday`（无需后端改动）

## 6. 验证标准

1. **显示**
   - 听背页进度行显示 `本条未听`（0 次）或 `本条已听 N次`（N>0）
   - 当日听过条目卡片标题显示 `今日已听` 徽标；进度行 `今日累计 M条` 随 `markExposed` 递增且刷新不丢（通过 `history?mode=listen` 重建）
   - 播完 ≥10s 后不刷新即可见 `已听次数` 自增
2. **排序**
   - 自定义范围选含 0/1/3 次且 `last_ts` 不同的条目集合，返回顺序必为：全部 0 次在前（内部按优先级），随后 1 次按 `last_ts` 早晚，再 3 次
   - 默认池与自定义池同输入同排序
3. **回归**
   - `pytest tests -q` 全绿；重点 `test_listen_queue_*`, `test_custom_listen_*`, `test_listen_marks_heard`, `test_plan_marks_reviewed_today` 通过（后者不受影响）
   - 手工：自定义范围 20/50/自定义数量 分批加载，`remaining` 递减正确

## 7. 范围边界

- 不做：覆盖率树按听学着色、音频预加载/变速记忆、SRS 间隔、listenedToday 服务端持久化键
- 不改：`reviews` 表结构、`TTS` 合成、`daily_plans`、`marks`
