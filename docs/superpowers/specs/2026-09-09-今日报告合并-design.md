# 今日 tab 与报告合并设计（Spec）

日期：2026-09-09 ｜ 状态：设计已审批，待实施

## 1. 背景与目标

今日页（`/`）与报告页（`/report` 复盘段）内容高度重叠：早报两处一字不差；
「今日数据」与今日 hero 进度环 + 计划 counts 是同一批数字换皮展示。
目标：去掉今日 tab，内容并入报告，删除重复与不必要部分；合并后以进度
和统计展示为主。

## 2. 导航与路由

- 底部导航改为三个 tab：学习 / 报告 / 我的（删除今日 tab 及 `IconToday` 引用）。
- `/` 路由保留，只做重定向到 `/study`（老书签、深链不 404）。
- 进应用默认落地学习页（看背视图，沿用 `/study` 现有默认）。
- 不涉及后端改动。

## 3. 报告复盘段结构（进度 + 统计图标为主）

复盘段内纵向排列，全部数据复用现有 `/api/today`：

1. **进度 hero**：进度环（看背+自测 done/quota 百分比）+ 考试倒计时徽标
   （≤17 天标红逻辑保留）+ 连续打卡 + 新学/复习/错题三数 +
   今日数据一行（看背+自测 done/quota、听学分钟、薄弱项）。
   即今日 hero、计划 counts、原「今日数据」三合一。
2. **计划 rationale**：缩成小灰字附于 counts 下方（数据优先，文案最小化）。
3. **今日复盘**（原晚报，见第 5 节）。
4. 覆盖 / 历史 / 排行 / 统计四个段原样不动。
5. 快捷入口三按钮（看背/听学/自测）删除：底部学习 tab 直达，报告内不再重复。

## 4. 早报删除清单

- 前端删除：今日页早报段、报告复盘早报段、`mdToHtml(morning_report)` 相关调用。
- 后端待核实后删除（实施前先 grep 确认有无他用，不误删共用代码）：
  - `/api/today` 响应中的 `morning_report` 字段组装；
  - 早报生成接口（`POST /api/reports/generate/morning` 如存在）；
  - 定时/调度中的早报任务；
  - 仅早报使用的 prompt 模板。
- 删除后全仓 grep `morning` 应只剩历史文档/spec 提及，无代码引用。

## 5. 今日复盘（原晚报）交互

- 前端改名「今日复盘」，定位一天结束（23:30 概念）的总结。
- 默认不自动生成：未生成时显示空态（"学完后来生成今日复盘"）+
  [生成今日复盘] 主按钮，点击后 loading → 展示内容。
- 已生成时展示内容 + [重新生成]，重新生成前加 `confirm` 确认
  （防误触消耗 token）。
- 后端 `kind=evening` 及相关接口保持不变，只改前端文案，零迁移、
  历史晚报数据继续展示。

## 6. 范围边界（不碰）

- 学习页（看背/听学/自测/错题）、报告其余四段、我的页、听学/自测逻辑均不动。
- 本 spec 不含：覆盖展示优化、听学断线重连、听学原文默认展开
 （用户另列事项，独立处理）。

## 7. 验证标准

- `npm run build` + `eslint` 通过；后端无改动（除早报删除涉及文件外，
  届时补 `pytest`）。
- 页面走查：`/` 跳学习页；底部三 tab；复盘段含 hero/计划小字/今日复盘，
  无早报残留；今日复盘可生成、可重生成（含 confirm）；覆盖/历史/排行/
  统计正常。
