# Spec：P0 口径修正 + P1 对标功能 + 全页面玻璃态 UI 重构

- 日期：2026-08-31
- 状态：待评审
- 前置：`docs/superpowers/research/2026-08-31-行业调研与功能盘点.md`（已审阅，范围确认：P0 四项 + P1 五项全做，另加全页面 UI 重构）
- 涉及模块：backend（service / routers / db / coverage / quiz_service / tests）、frontend（全部页面与组件 / globals.css / types / api）、docs

## 1. 背景与目标

行业调研结论：本工具差异化在"个人化记忆调度 + AI 报告答疑"，短板是行业标配的**错题本、记忆曲线可视化、打卡激励、限时模考**缺失，且存在 4 个统计口径/功能缺陷；当前 UI 为朴素白卡片风格，不符合"苹果玻璃态"级质感。

本轮目标：

1. 修正 P0 四项：完成率口径、覆盖树与调度状态统一、听学暴露判定、Web 导入 promote。
2. 落地 P1 五项：错题本、学习统计/记忆曲线、打卡连胜激励、智能组卷/限时模考、标记服务端化 + 速记本。
3. 全页面重构为玻璃态（glassmorphism）设计系统，无新增 UI/图表依赖。
4. 后端 pytest 全量回归 + 前端 build/lint + Playwright e2e 主链路验证，完成后推送远端。

## 2. 现状与问题（代码实读结论）

| # | 问题 | 证据 |
| --- | --- | --- |
| P0-1 | 完成率只算看背，自测/听学不计入 | `service.today_stats`：`done` 仅 `WHERE mode='read'` |
| P0-2 | 覆盖树与调度两套状态，quiz 错题不显示薄弱 | `coverage.entry_state`（last_result+count）vs `scheduler.classify`（+quiz_wrong） |
| P0-3 | 点开即跳也计"已听"，从未听池消失 | `ListenView.markExposed` 在跳过路径无条件触发 |
| P0-4 | Web 导入默认 draft，导入后不可见 | `importer.import_payload`：`status = payload.get("status","draft")` |
| P1-1 | 无错题本 | `quiz_answers`/`reviews(bad)` 数据已有，无聚合视图 |
| P1-2 | 无学习统计/记忆曲线 | `reviews` 按日聚合即可，无图表 |
| P1-3 | 无打卡/连胜 | 同上 |
| P1-4 | 自测仅每日 10 题，无自定义组卷/限时 | `quiz_service.build_daily_quiz` 固定流程 |
| P1-5 | 标记仅 localStorage，跨设备丢失 | `progressStore.LISTEN_MARK_KEY` |
| UI | 朴素白卡片，无质感 | `globals.css`（302 行） |

## 3. 方案概要

### 3.1 P0 修正

**P0-1 完成率口径**

- `today_stats.done` = 当天 `reviews(mode='read')` 条数 + 当天 `quiz_answers` 条数。
- `quota` 不变（当日计划条目数）；`percent = min(100, round(done/quota*100))`，`done > quota` 时前端显示"超额完成"。
- 听学维持 `listen_min` 单列；今日页/复盘页文案统一为"看背+自测 x/y · 听学 z 分钟"。

**P0-2 覆盖树与调度状态统一**

新状态判定（`coverage.entry_state` 扩展入参）：

| 状态 | 判定 |
| --- | --- |
| `new` 未学 | 无 read/listen/quiz 任何有效记录 |
| `weak` 薄弱 | 命中 retry 桶：最近 `result='bad'` 或 quiz 曾答错 |
| `mastered` 掌握 | 最近 `result='good'` 且 read 次数 ≥2 |
| `learned` 已学 | 其余有记录 |

- `coverage_payload` 查询补 `quiz_wrong_ever` 与 `has_record`；`cov.entry_state` 签名扩展，存量测试同步更新。
- `CustomRangePicker` 的"已学/未学"数量自动与统一后状态一致，无需改前端。

**P0-3 听学暴露判定**

- 手动「跳过」不再写 `reviews`（不视为已听）。
- `onPause`/`onEnded` 仅当 `duration_sec >= 10` 才记 `result='exposed'`。
- 队列"未听优先"排序与"已听"角标逻辑不变（以 listen 记录为准）。

**P0-4 Web 导入 promote**

- `router/import_.py`：导入前将 payload 注入 `status='final'`（面向最终用户；维护脚本 `import_entries.py` 行为不变）。
- 新增测试：Web 导入后条目 `status='final'` 且可被今日计划/自定义范围查到。

### 3.2 P1 功能

**P1-1 错题本（学习页第 4 tab）**

- 数据源：quiz 答错（`quiz_answers.correct=0`）+ 看背评 `bad`（`reviews.result='bad'`）。
- 新接口 `GET /api/wrongbook?limit=200`：按条目聚合 `wrong_count`（quiz 错 + bad 评）、`last_wrong_ts`；排序：最近错误时间倒序 → 错误次数倒序 → 科目顺序。
- 前端：学习页 segments 扩为「看背 / 听学 / 自测 / 错题」。
  - 错题列表卡片：科目·考点、错误次数、最近错误时间、「再看」「再听」。
  - 「开始重练」→ `/study?view=read&queue=wrong`：FlashcardView 支持 `queue=wrong`，队列取错题本前 N（默认 30），评分流程不变。
- 新增 `GET /api/wrongbook/queue?limit=30`（返回纯条目列表）供重练队列使用。

**P1-2 学习统计/记忆曲线（报告页新增「统计」segment）**

- 新接口 `GET /api/stats/overview?days=90`：

```json
{
  "days": 90,
  "daily": [{"date": "2026-08-31", "read": 3, "listen": 5, "quiz": 2}],
  "totals": {"read": 120, "listen": 260, "quiz": 30, "minutes": 180},
  "mastery": {"new": 800, "learned": 900, "weak": 120, "mastered": 484},
  "streak": {"current": 5, "longest": 12}
}
```

- 前端统计 segment：顶部连续天数徽标 + 累计计数；掌握度分布玻璃 chips；近 14 天日学习量 SVG 折线；近 12 周日历热力图（色深 = 当日总量）。图表全部 SVG/div 自绘，不引入图表库。

**P1-3 打卡/连胜激励（今日页）**

- `service.streak_info(conn, day)`：任一模式（read/listen/quiz）有记录即算学习日，倒序扫描得 `{current, longest}`。
- `/api/today` 增加 `streak` 字段；今日页头部增加玻璃态 SVG 进度环（percent）+ "连续学习 N 天"徽标。

**P1-4 智能组卷/限时模考（自测页新增「组卷」）**

- 新接口 `POST /api/quiz/custom {subjects, points, limit(1-50), timed}`：
  - 用 `service.custom_entries`（复用自定义范围过滤+排序）取前 N 条目；
  - 每题复用 `quiz_service` 当日缓存（`quizzes` 按 entry_id + date 查/建），不额外耗 LLM；
  - 返回与 `GET /api/quiz/today` 同构的 `{questions, timed, total}`。
- 前端 QuizView segments 扩为「今日 / 组卷 / 历史」：
  - 组卷入口：选择范围（复用 `CustomRangePicker`）+ 题量（5/10/20/自定义）+ 限时开关；
  - 限时模式：总倒计时 = 题数 × 60s，顶部倒计时，超时自动结束并提交当前题；
  - 答题/判分/解析复用现有流程。

**P1-5 标记服务端化 + 速记本（错题 tab 内）**

- 新表 `marks`（`db.py` SCHEMA_SQL 幂等新增，与现有无 Alembic 模式一致，同提交）：

```sql
CREATE TABLE IF NOT EXISTS marks (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  entry_id   TEXT NOT NULL REFERENCES entries(id),
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_marks_entry ON marks(entry_id, created_at);
```

- 新接口：
  - `GET /api/marks` → `{items:[{id, entry_id, created_at, entry:{...}}]}`
  - `POST /api/marks {entry_id}`（幂等：已存在返回既有记录）
  - `DELETE /api/marks/{mark_id}`、`DELETE /api/marks`（清空）
- 前端：
  - `ListenView` 标记按钮改调 API；首次加载时把旧 localStorage 标记一次性合并上传后清除（单用户设备迁移，失败则保留本地）。
  - 错题 tab「我的标记」区：列表 + 「重背」（深链 `?entry=`）+「查看」+ 取消标记/清空。
  - **速记模式**（抽问式背诵，对标觉晓速记本）：从「我的标记」进入，随机抽点条目显示 `point/anchor`（正面），点「显示结论」后自评（good/fuzzy/bad，写 `reviews mode='read'`），下一张；顶部显示 剩余/本轮进度；支持退出与重新进入。

### 3.3 全页面玻璃态 UI 重构

**设计系统（无新依赖，纯 CSS/SVG）**

- 背景：多层柔和 mesh 渐变（radial-gradient 蓝/靛/青光斑叠层），`prefers-color-scheme` 提供深色变体。
- 玻璃令牌：卡片 `rgba(255,255,255,0.55)` + `backdrop-filter: blur(24px) saturate(1.8)` + 1px 半透明白高光边 + 大半径柔和投影；`@supports` 降级为近实色。
- 圆角 16–24px；主色保留蓝系并升级为蓝→靛→青渐变；数字 `tabular-nums`；动效 `200ms ease-out`，卡片/按钮 active 微缩、入场 fadeUp。
- 图标：新增 `components/icons.tsx` 内联 SVG 集（今日/学习/报告/我的/AI/标记/火焰等），替换 Unicode 符号。

**改造清单**

| 组件/页面 | 改造点 |
| --- | --- |
| `BottomNav` | 悬浮玻璃胶囊底栏（blur + 圆角 + safe-area），active 渐变指示 + SVG 图标 |
| `Segments` | iOS 风格玻璃分段控件（active 滑块） |
| 按钮/徽标/计数 | glass / 渐变 primary / success / danger 体系 |
| `FlashcardView` | 玻璃翻转卡 + 光晕 + 渐变描边，评分按钮质感 |
| `QuizView` | 玻璃选项行、选中渐变描边、对错状态、组卷入口卡片 |
| `ListenView` | 播放卡、标记按钮、已标记徽标 |
| 报告页（复盘/覆盖/历史/排行/统计） | 玻璃卡 + SVG 图表 + 热力图 |
| 今日页 | 玻璃进度环 + 连胜徽标 + 计划卡 |
| 设置页 | 玻璃表单 |
| `CustomRangePicker`/`SourceViewer`/错题 tab | 底部 sheet 玻璃弹层 |
| `AiChat`/`AiFab` | 玻璃面板 + 气泡（用户渐变/AI 玻璃） |

**CSS 文件拆分**：`globals.css`（令牌/基础）+ `components.css`（组件体系）+ `charts.css`（图表/热力图）三个文件，`layout.tsx` 引入。

## 4. API 变更汇总

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/today` | GET | 增加 `streak` 字段 |
| `/api/wrongbook` | GET | 错题本聚合列表 |
| `/api/wrongbook/queue` | GET | 重练队列纯条目列表 |
| `/api/stats/overview` | GET | 日聚合 + 掌握度 + streak |
| `/api/quiz/custom` | POST | 智能组卷（含 timed） |
| `/api/marks` | GET/POST | 标记列表 / 添加（幂等） |
| `/api/marks/{id}`、`/api/marks` | DELETE | 删除单条 / 清空 |

## 5. 数据模型变更

- 仅新增 `marks` 表（含索引），随 `db.py` 同一提交生效（本仓库无 Alembic，沿用幂等 `CREATE TABLE IF NOT EXISTS` 模式；`alembic check/upgrade` 不适用，用 `pytest` + 建表冒烟验证）。
- `entries`/`reviews`/`quizzes` 等既有表结构不变。

## 6. 验证标准

1. `backend/.venv/bin/python -m pytest tests` 全量通过（147 + 新增用例）。
2. `frontend`：`npm run lint` + `npm run build` 通过。
3. Playwright e2e 主链路（localhost:3001）：今日页（进度环/连胜）→ 看背评分 → 听学播放与标记 → 自测 → 组卷限时 → 错题本重练 → 报告统计 → 玻璃态视觉走查截图。
4. 行数自查：新增/修改业务文件不超硬上限；`service.py` 超出 500 前完成拆分（本轮拆分 `stats.py` 模块承接统计/streak，错题本入 `review_stats`）。
5. 全页面截图走查（浅色 + 深色），确认无布局溢出。

## 7. 范围边界（不做）

- 不做用户账号/多设备同步（P2 保留）。
- 不做主观题批阅、直播/课程内容。
- 不引入 UI 框架、图表库、动画库（原生 CSS/SVG）。
- 不调整调度算法本身（仅统一状态口径）。
- 不动音频合成、条目生成/导入管线（Web 导入 promote 除外）。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 玻璃态在旧浏览器不支持 backdrop-filter | `@supports` 降级近实色；先桌面/现代移动端验证 |
| 全量 UI 重构改动面大，回归成本高 | 先完成功能，再分组件逐步替换样式；每阶段 e2e 走查 |
| 速记/组卷/错题交互细节多 | 交互以最小闭环为准（列表 → 队列/抽卡），复杂增强留 P2 |
| LLM 生成组卷题耗 token | 复用当日缓存，无新增生成；限时模式仅前端行为 |
| 旧 localStorage 标记迁移失败 | 合并上传逐个容错，失败保留本地并提示 |
