# 法条题卡「条目化」与条目卡完全统一 — Spec（2026-09-20）

## 1. 用户决策（已拍板）

1. **严格一致（方案 A）**：看背题卡不再"点选项判分"，与条目卡一样"翻面 + 三档自评"。
2. **同意拆文件**：`FlashcardView.tsx`(603 行) / `ListenView.tsx`(457 行) 按 §4 拆分。
3. **题卡标记要做**。
4. **统计计入**："今日累计 / 累计已听"等把题卡计入。
5. **不新建表、不要两套逻辑**：题卡按条目模型"重建"，能复用的一律复用，
   看背/听学是最核心入口，维护成本必须低。
6. **卡片 ID 按科目分类**：沿用 8 科前缀 + `-Q` 标识（如 `XF-Q000162`），与正式条目不冲突。
7. **卡片 priority 统一「普通」，不强制混排**：按原有优先级排序，高优先级的条目学完，
   自然轮到普通（含卡片）。
8. **判断题（origin='judge'）不做卡片**（2026-09-20 追加）：卡片只做法条驱动**客观题**
   （`origin='bank'`，当前 12052 题）；历史遗留的判断题卡片由同步脚本删除。

## 2. 方案：题卡条目化（核心）

把每道法条驱动题重建为一条 **entries 行**（`kind='card'`），题目文本进入条目字段，
于是看背/听学/标记/自评/错题本/统计/音频全部走**同一条既有代码路径**，零新增表。

### 2.1 表结构（只加列，不加表）

```sql
ALTER TABLE entries ADD COLUMN kind TEXT NOT NULL DEFAULT 'entry';
ALTER TABLE entries ADD COLUMN options TEXT NOT NULL DEFAULT '[]';
ALTER TABLE entries ADD COLUMN article_text TEXT NOT NULL DEFAULT '';
```

`kind`：`'entry'`（正式条目） | `'card'`（法条题卡）；
`options` / `article_text`：卡片专用（选择题选项、条文摘要），正式条目留默认值。
幂等升级写在 `db.connect()`（本仓库无 Alembic，沿用现有 ALTER 模式）。

### 2.2 卡片条目生成（`scripts/sync_card_entries.py`，幂等可重跑）

来源：`quizzes` 中 `origin='bank' AND status='published' AND entry_id IS NULL
AND basis != ''`（当前 12052 题，全部为客观题）。**`quizzes.entry_id` 保持 NULL 不动**，
因此覆盖率、审计脚本、判断题脚本的既有口径完全不变。判断题不进卡片（§1.8），
`card_entries.CARD_ORIGINS` 是唯一开关。

| entries 列 | 卡片取值 |
|---|---|
| `id` | `<科目前缀>-Q<quiz_id 六位>`，如 `XF-Q000162`（按科目分类，题目↔卡片 1:1 可反查） |
| `kind` | `'card'` |
| `subject` | 题目科目（8 科口径内） |
| `submodule` | 法条库主名（`statutes.resolve_law_article` 解析；失败填「法条题」） |
| `point` | `<法条主名>第<条号>条 · <题干前 24 字>` |
| `anchor` | 题干 `stem` |
| `conclusion` | 正确答案 `answer`（选择题为选项字母/组合） |
| `rationale` | 解析 `analysis` |
| `priority` | `'普通'`（卡片不进调度优先级计算） |
| `statutes` | `[basis]`（前端「依据」chip，点开法条原文） |
| `sources` / `cases` / `note` | `[]` / `[]` / `NULL` |
| `options` | 题目选项（客观题必有，cloze 题为空数组） |
| `article_text` | 条文原文摘要（`statute_cards.snippet`，160 字） |
| `tts_text` | `statute_cards.listen_text()`：依据 → 条文摘要 → 题干 → 选项 → 答案 → 解析 |
| `status` | `'final'` |

同步策略：按 `text_hash`（题干 + 答案 + 解析 + 条文）检测漂移 → 更新文本、删除旧音频
（`data/audio/<卡片ID>.wav`）与 `tts_assets` 台账；题库下架（`archived`）→ 卡片 `status='draft'`。
卡片数据源是已进版本库的 `data/quiz_bank/*.json`，**无需往 `data/entries/*.json` 写卡片**。

**ID 按科目分类**（沿用现有 8 科前缀，卡片再加 `-Q` 标识，与正式条目 `XF-001` 形态不冲突）：

| 科目 | 前缀 | 卡片示例 |
|---|---|---|
| 商经知劳环 | `SJ` | `SJ-Q003218` |
| 三国法 | `SG` | `SG-Q000145` |
| 理论法 | `LL` | `LL-Q001077` |
| 刑诉 | `XS` | `XS-Q000902` |
| 民诉 | `MS` | `MS-Q000431` |
| 民法 | `MF` | `MF-Q007765` |
| 行政法 | `XZ` | `XZ-Q000260` |
| 刑法 | `XF` | `XF-Q000162` |

反查：`quiz_id = int(entry_id.split("-Q")[1])`（`id` 里含 `-Q` 即卡片，配合 `kind='card'` 双保险）。

### 2.3 队列：卡片作为「普通」条目进入原有池子，**不强制混排**

卡片 `priority='普通'`，直接参与现有排序，不写任何"每 3 条插 1 张"的注入逻辑：

- 看背：`ensure_today_plan` 的调度池（`FROM entries WHERE status='final'`）现在含卡片，
  `_sort_key = (read_count, 优先级, 科目, id)` → 高频考点 / 易错陷阱 / 新增必考先学，
  正式条目里的普通项学完，自然轮到卡片。
- 听学：`_sort_listen_items` 已是「未听优先 → 次数少 → 久未听 → **优先级** → 科目 → id」，
  卡片同样排在低频优先级之后，顺序规则零改动。

| 入口 | 变更 |
|---|---|
| 看背 `GET /api/plans/today` | 删除 `statute_cards` 字段（卡片本来就在调度池里） |
| 听学 `GET /api/listen` | 删除 `statute_cards` 字段（卡片本来就在听学池里） |
| 自测 / 组卷 | 不变：仍用 `statute_cards.pool(mode='quiz')` 每 3 题留 1 题（作答判分留在这一侧） |
| 法条页 | 不变：`statute_cards.by_article` |

前端拿到的就是**一个 `items` 数组**：进度行编号、上一个/下一张、队列持久化、
徽章（已看 N 次 / 今日已看 / 已听 N 次）、三档自评、标记、问 AI、错题重练队列全部复用现有实现。

### 2.4 复用清单（不新增任何表 / 接口）

| 能力 | 复用对象 |
|---|---|
| 三档自评 | `POST /api/reviews` → `reviews(entry_id='XF-Q000162', mode='read')` |
| 听学暴露 | `POST /api/reviews`（`mode='listen'`，阈值 `min(8s, 时长×0.8)`） |
| 标记 | `POST/DELETE /api/marks` → `marks(entry_id='XF-Q000162')` |
| 音频 | `GET /api/audio/{id}` → `data/audio/XF-Q000162.wav` + `tts_assets` 台账 |
| 徽章 / 统计 | `review_stats`（看/听次数、今日已看/已听、累计） |
| 错题本 | `reviews.result='bad'` 聚合 → 看背「没记住」的卡片自动进错题本，可在同一套卡片里重练 |
| 问 AI | `useAiShortcut(entry)`（卡片有 point/anchor/conclusion 即可用） |

**删除**：`/api/cards/statute`、`/api/cards/seen`、`/api/cards/stats`、`StatuteCardView.tsx`、
`ListenCardView.tsx`，以及 `card_seen` 的 read/listen 写入（表保留，避免迁移风险）。

## 3. 条目空间隔离（本方案最大风险点）

entries 从 2426 行涨到约 15586 行，所有"按条目语义"的读取必须排除卡片，否则会污染
报表、覆盖率、搜索、批量 TTS、案例匹配、出题脚本。

做法：

1. `db.py` 加只读视图 **`v_entries`**：`SELECT * FROM entries WHERE kind='entry'`；
2. 现有 43 处 `FROM entries` / `JOIN entries` 逐处归属：

| 归属 | 处理 |
|---|---|
| 条目空间（调度、计划种子、搜索、历史/排行榜、报表、统计、覆盖率、案例匹配、`generate_entries` / `build_*_bank` / `audit_*` / `synthesize_audio` / `repair_tts` / `import_` / `quiz_bank_io`） | 改用 `v_entries` |
| 卡片可见（`entry_by_id`、`marks` 面板、`/api/audio/{id}`、review 历史、错题本、看背/听学队列） | 保持 `entries` |

3. 写路径（`import_entries.py`、`update_entry_text`、sync 脚本）仍写 `entries` 表，按 id 精确定位；
4. 单测断言：`/api/entries`、关键词搜索、统计、覆盖率、`synthesize_audio` 候选都不含卡片行
   （`kind='card'`，`id` 含 `-Q`）。

## 5. 范围外

- 自测、组卷、法条页保持 quizzes 侧作答判分；`quizzes.entry_id` 保持 NULL，
  所以「自测里法条题答错」仍不进错题本（现状），而看背「没记住」的卡片会进（新行为，符合一致性）。
- 不改 TTS 供应商链；卡片音频仍走阿里云 TTS，进入听学队列时按需合成。
- 不动 `AGENTS.md` / `README.md`（并发协作者正在改，避免冲突）。

## 6. 风险

1. **43 处 SQL 的归属判定**：漏一处就会让卡片泄漏进条目空间。缓解：视图化 + 单测 +
   上线前自查 `COUNT(entries) - COUNT(v_entries)` 应等于卡片数。
2. **entries 体量 ×6.4**：DB 增大、全表扫描变慢；卡片行文本较短，现有索引不受影响，
   压测后再决定是否加索引。
3. **批量 TTS 成本**：`synthesize_audio.py` 若不隔离会去合成 12052 条卡片音频（大额花费），
   必须走 `v_entries`，卡片音频只按需合成。
4. **重建时机**：题库每次 `--publish` 后需重跑 `sync_card_entries.py`（幂等）；
   补进 AGENTS 3.5b 待办，等并发协作者改完 AGENTS 再动。
5. **卡片会逐渐占满每日计划**：卡片 12052 张、优先级"普通"，当正式条目的高频 / 易错 /
   新增必考复习完之后，看背与听学的队列会主要由卡片组成（按每天 30 张约需 400 天走完）。
   听学因为是"未听优先"，卡片会排在已听过的条目之前（实测前 20 段 19 张卡片），
   如需"同优先级正式条目先于卡片"，在 `_sort_listen_items` 增加一层 kind 排序键即可。
   这正是"高优先级先学、普通自然轮到"的预期结果；上线后看一周数据，若节奏不合适再谈
   限流或按科目筛卡（本次不做）。
