# 案例库阅读导航与看阅进度 — Spec（2026-09-22 增补）

## 1. 需求

现有 `/cases` 只能「列表点进去读 → 滚动回顶部点返回 → 再点下一篇」：

1. **加「上一篇 / 下一篇」**：读案例时不用回列表、不用滚到顶部就能连续读；
2. **加「已看过 / 未看过」标识**：列表里能一眼看出哪些读过；
3. **加阅读历史**：能回到「刚才读的几篇」；
4. **优先展示未看过的**：默认把没读过的排在前面，读过的沉底。

## 2. 现状与约束

- 阅读视图不是独立路由，是 `/cases?lib=<来源>&loc=<定位符>` 这一个 URL 状态；
  列表的查询词/筛选/排序**不进 URL**，一旦进阅读视图就丢了（返回后筛选也丢）。
- 「上一篇 / 下一篇」依赖「当前阅读顺序」，而顺序由列表的 `q + source/field/crime/year/sort`
  决定。因此**这些参数必须进 URL**，阅读视图才能算出前后篇。
- 排序（含「未看过优先」）必须作用在**全库命中集**上，不能只在前端已加载的一页里重排，
  否则「未看过」的案例沉在 7000 篇后面永远翻不到 → 看阅状态**放服务端**（SQLite），
  而不是 localStorage。
- 本仓库无 Alembic，新增表靠 `backend/app/db.py` 的 `SCHEMA_SQL`
  （`CREATE TABLE IF NOT EXISTS`，连接时执行）。

## 3. 方案概要

服务端新增一张 `case_views` 阅读记录表（单用户本地库，一条案例一行），承载三件事：

| 能力 | 实现 |
|---|---|
| 已看过 | 打开阅读视图时 `POST /api/case/view` 打点（幂等 upsert，`views` 计数） |
| 历史记录 | `case_views.last_viewed_at` 倒序 + JOIN `cases` 取标题 |
| 未看过优先 | `sort=unviewed`：未看过的一组在前、看过的一组在后，组内仍按原顺序 |

「上一篇 / 下一篇」用服务端现算：`GET /api/case/neighbors` 复用同一套
筛选 + 排序逻辑，返回当前篇在**全库命中顺序**里的前后项。

## 4. 数据模型

```sql
CREATE TABLE IF NOT EXISTS case_views (
  source          TEXT NOT NULL,          -- 来源库，与 cases.source 同口径
  loc             TEXT NOT NULL,          -- 定位符，与 cases.loc 同口径
  first_viewed_at TEXT NOT NULL,          -- 首次打开时间（ISO）
  last_viewed_at  TEXT NOT NULL,          -- 最近打开时间（历史排序键）
  views           INTEGER NOT NULL DEFAULT 1,
  PRIMARY KEY (source, loc)
);
CREATE INDEX IF NOT EXISTS idx_case_views_last ON case_views(last_viewed_at);
```

- 不建外键：案例库重装（`load_cases.py`）时不应因阅读记录阻塞，悬空记录由 JOIN 自然过滤。
- 不加 `title` 冗余列：历史展示的标题一律 JOIN `cases` 取，避免两份真相。
- 阅读记录**不随案例库重装清空**（重装后 loc 不变，记录仍有效）。

## 5. API 设计

### 5.1 `GET /api/case/search`（扩展）

| 参数 | 说明 |
|---|---|
| `sort` | 新增 `unviewed`（未看过优先；有 `q` 时组内按相关度，无 `q` 时组内按最新） |
| `viewed` | `""`（默认，全部）/ `no`（只看未看过）/ `yes`（只看已看过） |

`items[]` 新增字段 `viewed: bool`；`filters` 回显新增 `viewed`。

### 5.2 `GET /api/case/neighbors`（新增）

参数：`lib` + `loc`（当前篇身份）+ `q`/`source`/`field`/`crime`/`year`/`sort`/`viewed`
（当前阅读上下文，与 `search` 同口径；此处 `source` 仍是**来源库筛选**，身份用 `lib`）。

```json
{"index": 0, "total": 2645,
 "prev": {"source": "最高检指导性案例", "loc": "检例第257号", "title": "…", "date": "2026-08-05"},
 "next": {"source": "最高检指导性案例", "loc": "检例第259号", "title": "…", "date": "2026-08-05"}}
```

语义（关键，因为「打点」会立刻改变本篇在排序里的位置）：

| 字段 | 取法 | 理由 |
|---|---|---|
| `next` | 当前上下文的排序里，当前篇**当作「未看过」**定位后的下一项 | 打点后本篇会沉到「已看过」组末尾，否则下一篇永远是空 |
| `prev` | 阅读轨迹上一篇（`case_views.previous_view`：比本篇更早打开的那篇） | 「未看过优先」下刚看过的那篇已不在本篇前面，只有轨迹能原路返回 |
| `index`/`total` | 上面那套排序里的位置与总数 | 首次阅读时显示「第 N / M 篇」 |

- 复用 `case_index` 的筛选/排序函数，**不复制一套排序口径**。
- `viewed=no` 筛选在相邻篇里被忽略：打点后本篇不再匹配该筛选，否则前后篇全空。
- 首篇 `prev=null`、末篇 `next=null`；当前篇不在命中集（上下文与案例不匹配，
  例如从历史记录带着旧关键词跳进来）时 `index=-1`、`next=null`，
  但 `prev` 仍按轨迹返回，前端只隐藏「下一篇」。

### 5.3 `POST /api/case/view`（新增）

请求 `{"source": "...", "loc": "..."}`，幂等 upsert，返回
`{"source","loc","views","first_viewed_at","last_viewed_at","first_time"}`；
`first_time=true` 表示这次是首次打开（前端显示「首次阅读」）。案例不存在 → 404。

### 5.4 `GET /api/case/history`（新增）

`?limit=30`（≤200）→
`{"items":[{source,loc,title,category,case_no,date,first_viewed_at,last_viewed_at,views}], "total": N}`，
按 `last_viewed_at` 倒序。`DELETE /api/case/history` 清空阅读记录（用于「重置阅读进度」），
返回 `{"cleared": N}`。

## 6. 前端设计

### 6.1 上下文进 URL（修既有缺陷）

- 列表点开案例时 URL 带全上下文：`q + lib + loc + field + crime + year + sort + viewed`。
- 列表页初始化筛选状态**从 URL 读**（此前一律重置为空）→ 从阅读视图返回保留筛选。
- 新增 `lib/caseNav.ts`：URL ⇄ 上下文（`filtersFromParams` / `readerContextFromParams` /
  `searchPath` / `readerPath` / `neighborPath`），列表页与阅读视图共用一份口径。

### 6.2 阅读视图（`components/CaseReader.tsx` 新增）

- **吸顶导航条**（`position: sticky`）：`← 返回` ｜ `上一篇` ｜ `下一篇` ｜ `第 N / M 篇` ｜
  阅读状态徽标 —— 解决「必须滚到顶部才能返回」；`第 N / M` 让用户知道读到哪儿。
- **键盘快捷键** `←` / `→` = 上一篇 / 下一篇（输入框聚焦时不触发）。
- 进入即 `POST /api/case/view` 打点，**打点在取 neighbors 之前**（服务端据此把本篇
  当作「未看过」定位、并把上一篇算成轨迹上一篇）；同一篇只打一次点（`useRef` 去重，
  否则 dev 严格模式的二次挂载与父组件重渲染都会重复计数）。
- 「第 N / M 篇」只在**本次首次阅读且无阅读状态筛选**时展示（否则是打点后的临时位置），
  其余情况只显示「首次阅读 / 已看过 N 次」。
- 无上一篇/下一篇时按钮置灰；`index=-1` 时「下一篇」置灰但仍可「上一篇」退回。
- 正文仍用现有 `CaseDocument`，不改文书分节逻辑。

### 6.3 列表

- 每条命中显示 `已看` 徽标（`viewed=true` 时）。
- 默认排序 `未看过优先`（`CaseSort` 新增 `unviewed`；检索时仍可切回「相关度」）。
- 高级筛选面板新增「阅读状态」：全部 / 未看过 / 已看过（复用 `caselib-filter` chips）。
- `components/CaseHistoryPanel.tsx`（新增）：筛选条下方的可折叠「最近看过（N）」，
  打开时拉历史、显示标题 + 来源 + 时间，点条目直接进阅读视图，附「清空历史」。

## 7. 范围边界

- 不改 `cases` 表、不改案例装载/文书分节逻辑，只新增 `case_views`。
- 不做「阅读时长/进度百分比/跨设备同步」；单用户本地库即事实来源。
- 不改 `/api/case/detail`（阅读视图的「看过」状态由 `/view` 回应与列表徽标体现）。
